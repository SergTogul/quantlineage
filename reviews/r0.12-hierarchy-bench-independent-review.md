### 1. VALID — Minor — Hierarchy contract is still comment-blind and token-wide

- Files: `backend/tests/test_nightly_ci.py` L34–58, L198–236; `backend/tests/test_pr_full_ci.py` L39–69
- What's wrong: Same helpers as R0.12.2 / R0.12.4 / QuantLib E2E Minor (`_needs_ids` unanchored inline `needs: […]`, `_on_block` raw text, job-block substring locks). Specified honest mutations fail. These hunts stay **green**:
  - comment-first `# needs: [backend, backend-quantlib, frontend, lint, e2e, postgres-smoke]` plus listed `needs:` that also includes `hierarchy-benchmark` (`_needs_ids` returns the comment; exact-six and `hierarchy-benchmark not in needed` both pass)
  - `if: false` on `hierarchy-benchmark` (no `if:` lock; only `continue-on-error` is asserted)
  - replace the real `python benchmarks/run_hierarchy_bench.py --json` pipeline with a comment that keeps those tokens plus `echo '{"impl":"hierarchy_python",…checksum…}'` (required tokens remain; `echo-only` is a literal string check)
- Why it matters: Acc 1’s exact strings are locked. A later comment-only PR-FULL leak, a skipped job, or an echo that keeps tokens does not fail the suite. GHA itself would error if `ci.yml` `needs:` a job that does not exist in that workflow, so the comment-first leak is not a live PR blocker today. On disk the job runs the bench script and `assert row['checksum'] == '2a51c377…'`.
- Suggested fix: Parse `on:` / `needs:` / job steps with a YAML loader. Forbid `if:` / `continue-on-error` on `hierarchy-benchmark`. Require a `run:` line that invokes `python benchmarks/run_hierarchy_bench.py --json` (not merely those substrings) and a following `assert` of the pinned checksum.
