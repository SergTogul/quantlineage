## Findings from the first review

### 1. Tree uniqueness is not structural; raw trade `id` collides in legal books — CLOSED

Original: trade-level id was the raw position id (`""`/`None` → `"trade"`);
PORTFOLIO returned raw `portfolio_id`. Legal books collided:
`portfolio.id == trade.id`; empty vs `"trade"`; trade `desk:Rates Desk`;
books `""` vs `"book"`. Fixture-only uniqueness tests stayed green.

Now: every `build` / `risk_at` / `portfolio_at` id goes through
`hierarchy_node_id`. Internal `book_pf.id` / `trade_pf.id` use the same
helper (the first review’s inline-string leftover is gone). In-memory
`HierarchyEngine.build` on the four legal books (no production edits):

| Book | Node ids | Duplicate? |
|---|---|---|
| `Portfolio(id="eq-a")` + trade `eq-a` (and `eq-b`) | `portfolio:eq-a` vs `trade:…/eq-a` | no |
| position `id=""` under Cash A, `id="trade"` under Cash B | `trade:D/S/Cash A/` vs `trade:D/S/Cash B/trade` | no |
| trade `id="desk:Rates Desk"` | `desk:Rates Desk` vs `trade:…/desk:Rates Desk` | no |
| books `""` and `"book"` under D/S | `book:D/S/` vs `book:D/S/book` | no |

`len(ids) == len(set(ids))` and all ids nonempty on each tree.
`_assert_unique_nonempty_ids` is used by the new tests.

### 2. Engine-built portfolio node can have empty `id` — CLOSED

Original: `hierarchy_node_id("portfolio", …)` returned `portfolio_id`
verbatim; `Portfolio(id="")` built a portfolio node with `id=""`.

Now: `portfolio:{_seg(portfolio_id)}` → `portfolio:` for empty book id.
Probe and `test_empty_portfolio_id_is_namespaced_and_nonempty` both see
a nonempty namespaced id. Default `HierarchyNode.id = ""` remains a
payload/OpenAPI default, not an engine result.

### 3. Slash-delimited strategy/book ids are ambiguous — CLOSED

Original: `strategy:Rates/Extra/Carry` could be desk=`Rates/Extra` +
strategy=`Carry` or desk=`Rates` + strategy=`Extra/Carry`.

Now: `_seg` encodes `%` → `%25` then `/` → `%2F` (order is injective for
those two characters). Helper:
`strategy:Rates%2FExtra/Carry` ≠ `strategy:Rates/Extra%2FCarry`.
In-memory tree with both positions in one book: 10 nodes, 10 unique ids
(`desk:Rates%2FExtra` vs `desk:Rates`, and the two strategy ids above).
Literal label `A%2FB` becomes `A%252FB` and does not collide with `A/B`.
`test_slash_in_desk_and_strategy_labels_do_not_collide` locks the helper
inequality. `path` is still an unencoded breadcrumb (leftover display
ambiguity, not an id collision).
