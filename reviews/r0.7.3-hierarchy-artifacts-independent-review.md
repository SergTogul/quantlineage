## Findings

### 1. VALID — Minor — artifact-path VaR / ES / limits occupy computed-risk fields as zeros

- Files: `backend/app/risk/hierarchy.py` L281–287;
  `backend/app/domain/models.py` L1275–1305 (`HierarchyNode`, not edited);
  `backend/tests/test_hierarchy_artifacts.py` (no `var_*` / `limits`
  asserts);
  `reviews/r0.7.3-hierarchy-artifacts-report.md`
- What's wrong: `_node_from_artifacts` writes `var_95=0.0`,
  `var_99=0.0`, `expected_shortfall_99=0.0`, `limits=[]`. Those are the
  same required floats / list as the reprice path. A consumer cannot
  tell omitted tail risk from a computed zero-risk book. Tests never
  pin the zeros or an omission flag. `build`'s docstring still says
  “NAV/Greeks/VaR/ES/stress/limits per node.”
- Why it matters: Anyone who wires the new `artifacts=` path into the
  existing hierarchy API/UI will display `$0` VaR / ES and “no
  limits.” That is not computed risk. It is also not a fake RF-008
  close: the report calls the zeros omitted, node VaR-from-vector
  later, and RF-008 not closed.
- Suggested fix: Keep RF-008 open. When node VaR lands, derive it from
  summed `historical_pnl` (or fail closed if the vector is missing).
  Until then, pin `assert root.var_95 == root.var_99 ==
  root.expected_shortfall_99 == 0.0` and `assert root.limits == []` so
  invented non-zero tails cannot sneak in, and do not serialize these
  fields as if a risk run computed them. Optional / Lead Architect:
  `None` or an explicit omitted flag on `HierarchyNode` (schema
  change; not required to approve this leftover).

### 2. VALID — Minor — `risk_at` incomplete map raises `KeyError`, not the documented `ValueError`

- Files: `backend/app/risk/hierarchy.py` L303–305 (`_scenario_ids`
  before `_require_complete_artifacts`);
  `backend/tests/test_hierarchy_artifacts.py` L206–228 (incomplete /
  key-mismatch only call `build`)
- What's wrong: `risk_at` normalizes, then indexes
  `artifacts[position.id]` inside `_scenario_ids`. A missing trade
  raises `KeyError` (`'eq-b'`). `build` raises `ValueError`
  (`incomplete artifact set; missing trade ids: ['eq-b']`). Probe
  confirmed. Still fail-closed (no mix with `_metrics`). Untested.
- Why it matters: Callers catching `ValueError` / `incomplete` on
  `risk_at` will not see the documented error. A later change that
  moved `_scenario_ids` after `_node` could also change the failure
  mode without a red test.
- Suggested fix: Call `_require_complete_artifacts(sub.positions,
  artifact_map)` in `risk_at` before `_scenario_ids`. Add the same
  incomplete / key-mismatch cases on `risk_at`.
