# R0.2 FX Forward / Option Snapshot Authority Independent Review

Slice: family B — when `market is not None`, `FXForwardPosition` and
`FXOptionPosition` require `fx_spots[pair]`, option `fx_vols[pair]` (or a
usable `vol_surfaces[pair]` quote), `rates[domestic]` (`pair[-3:]`), and
`rates[foreign]` (`pair[:3]`); missing keys raise `MissingMarketDataError`.
`market is None` still uses trade-local marks (compatibility; not scored
for REQUEST CHANGES).
Workspace: uncommitted work on `r0-core-remediation` vs HEAD.
Implementer report: `reviews/r0.2-fx-report.md` (claims, not proof).
Production files were not modified by this review. Index, HEAD, and
branch were not mutated. RF-001 was not closed.

## Verdict: APPROVE

Both pricers fail closed on a supplied snapshot that omits the pair spot,
option vol (no usable surface and no `fx_vols[pair]`), domestic USD rate,
or foreign EUR rate. They still price from trade-local `spot` /
`volatility` / `domestic_rate` / `foreign_rate` when `market is None`.
QuantLib consumes the overlayed marks, not the caller’s original fields.
I verified that in source and at runtime, including in-memory `.get`
restores. Canned `global-macro` demo and aggregate snapshots already
seed EURUSD spot, vol, USD, and EUR; SAMPLE FX names price against both.

No leftover `fx_spots.get(pair, position.spot)`,
`fx_vols.get(pair, position.volatility)`, or
`rates.get(..., position.domestic_rate / foreign_rate)` remains on the
supplied-market FX path in `builtin.py`, `quantlib.py`, or
`surface_vol.py`. Residuals are the same deferred helper-duplication and
error-shape notes as prior R0.2 family slices. Bond/swap/IR `.get`
fallbacks and omitted-`market=` inference were not scored.

## Attack results

1. **`fx_spots.get(pair, position.spot)`.** Gone from both pricers on the
   supplied-market path. Builtin uses `_required_fx_spot`; QuantLib
   overlay does the same before `_fx_forward` / `_fx_option` read `p.spot`.
2. **Domestic/foreign `.get(..., position.*_rate)`.** Gone. Both engines
   call `_required_settlement_rate(market, pair[-3:])` and
   `pair[:3]`. USD-only snapshots raise `rates[EUR]`; they do not
   silently take `position.foreign_rate=0.01`.
3. **Option vol → `position.volatility` when snapshot has no `fx_vols`
   and no usable surface.** Gone. Builtin and QuantLib overlay call
   `required_fx_option_vol`, which has no trade-mark argument.
   `option_vol_from_snapshot(..., fallback=)` is no longer on the FX
   engine path. Empty / wrong-pair `fx_vols` raise.
4. **One engine fail-closed, the other leftover.** Not found. Overlay
   raises before the QuantLib session if a required FX key is absent.
   `_black_vol_handle` may still use `flat_vol=p.volatility` when no FX
   surface is attached; after overlay that scalar is the snapshot vol.
5. **Tests only Builtin / only Settings / ZCB-only.** Not found.
   Matching missing-key cases exist in `test_quantlib_pricing.py` and
   invoke `engine.value`. No new case asserts `Settings.evaluationDate`
   instead of a raise or PV.
6. **Happy-path tolerances weakened.** Not found. See criterion 8.
7. **RF-001 marked CLOSED.** Not found.
8. **`market is None` broken.** Not found. CIP / GK no-market PVs match
   trade marks on both engines; golden and parity tests still call
   `value(position)`.

## Findings

### 1. VALID — Minor — Required FX helpers are duplicated

- Files: `backend/app/pricing/builtin.py`,
  `backend/app/pricing/quantlib.py`
- What's wrong: Identical `_required_fx_spot` functions now sit next to
  the already-duplicated `_required_settlement_rate` /
  `_required_equity_spot` pairs. `required_fx_option_vol` is correctly
  shared.
- Why it matters: A later pair-validation (RF-011) or trade-id error
  change can tighten one copy and leave the overlay on the old
  contract. Not a current behavior bug — both raise the same
  `factor_key` today.
- Suggested fix: One shared helper next to `MissingMarketDataError`.
  Same deferred class as prior R0.2 slices.

### 2. VALID — Minor — `MissingMarketDataError` still names only the factor key

- File: `backend/app/market/demo_snapshot.py` (unchanged this slice)
- What's wrong: Brief §3 asked the typed error to name trade id **and**
  factor key. Call sites still pass only `fx_spots[EURUSD]` /
  `fx_vols[EURUSD]` / `rates[USD]` / `rates[EUR]`.
- Why it matters: Same shape as approved R0.2 equity slices. Logs for a
  multi-pair book will not say which trade failed. Not a silent
  fallback.
- Suggested fix: Thread `position.id` into the error when the helpers
  are unified.

## Items checked and not findings

- Builtin no longer calls `fx_spots.get` / `fx_vols.get` /
  `rates.get(pair[-3:], position.domestic_rate)` when `market is not None`.
- QuantLib copies onto a local `model_copy`; the caller position is not
  mutated. Overlay raises before the session if the key is absent.
- `market.fx_spots` / `fx_vols` / `rates` are mapping proxies; `[]`
  still raises `KeyError` and is translated. Present `0.0` would be a
  valid mark, not missing.
- `MarketSnapshot.rates` default `{"USD": 0.04}` means omitting `rates=`
  is not a missing-USD-rate case. A snapshot that omits `rates=` still
  raises `rates[EUR]` for EURUSD. Tests isolate USD with `rates={}`.
  Pre-existing schema; not introduced here.
- Pair parsing remains `pair[-3:]` / `pair[:3]`. Documented RF-011
  leftover; not a trade-mark bypass.
- Empty `vol_surfaces[EURUSD]` (`grid: {}`) raises `ValueError`
  (“surface requires at least one point”) rather than
  `MissingMarketDataError` or a trade-mark price. Same “raw is not
  None ⇒ treat as usable” shape as `required_equity_option_vol`. Not a
  `.get` leftover; do not REQUEST CHANGES on this slice for it.
- An equity-class surface stored under `EURUSD` is treated as usable by
  `required_fx_option_vol` (no `asset_class` check). QuantLib
  `_black_vol_handle` requires `asset_class == "fx"` and would then use
  the overlayed point vol. Still not a trade-local fallback.
- `option_vol_from_snapshot(..., fallback=0.0)` inside
  `required_fx_option_vol` is dead on the surface-present branch
  (`raw is None` cannot hold). It cannot revive `position.volatility`.
- `_DEMO_MARKETS` / `_DEMO_AGGREGATE_MARKETS` `equity-vol` and
  `rates-macro` omit FX keys. Those canned books have no FX positions.
  `global-macro` / SAMPLE is the FX demo path and is seeded.
- Attribution FX `.get` leftovers and bond/swap/IR fallbacks remain.
  Out of severity per the review request.
- `test_sensitivities.py::test_fx_delta_forward_and_option` still prices
  with `market is None` and stayed green.
- `test_attribution.py::test_fx_move_explained_by_fx_bucket` supplies
  EURUSD spot plus USD and EUR rates and stayed green.
- Cache identity remains `legacy_position_v1` for this family
  (implementer limitation). Not a fail-open pricing path.
- I did not close RF-001. Family B spots/vol/rates on the explicit
  snapshot path are done; terms split, other families, and
  omitted-`market=` inference remain.
