# R0.11.2 Finite financial numbers

## Task
R0.11.2 Finite financial numbers (RF-014 / SEC-006)

## Owner
Backend / API Engineer

## Summary
Added a shared `FiniteFloat` constraint (`Annotated[float, BeforeValidator..., AfterValidator(math.isfinite)]`) and applied it to financial scalars on position, market, and scenario *request* models. `Field(gt=0)` no longer lets `+Infinity` through on maturities, vols, notionals, and similar fields. JSON `NaN` / `Infinity` / `-Infinity` on portfolio-bearing routes now fail request validation with HTTP 422.

FX position `pair` fields accept a 6-letter ISO shape (e.g. `EURUSD`) and reject clearly invalid strings. Magnitude caps were not added.

`MarketSnapshot.bump` / `apply` / `diff` logic was not changed. Non-finite values are rejected at construction/validation only.

## Files changed
- `backend/app/domain/models.py`
- `backend/tests/test_finite_scalars.py`
- `reviews/r0.11.2-report.md`

## Public/interface changes
- New shared types: `FiniteFloat`, `FxPair`.
- Position financial scalars (quantity, price, spot, strike, vol, rates, notionals, `maturity_years`, `option_maturity_years`, durations, etc.) reject non-finite values.
- `MarketSnapshot` typed float maps (`equity_spots`, `equity_vols`, `fx_spots`, `fx_vols`, `rates`, `key_rates`, `dividend_yields`, `projection_rates`, `rate_spreads`) reject non-finite values. Nested `curves` / `vol_surfaces` floats are also rejected on construction.
- Scenario / reverse-stress / limit / attribution / what-if / risk-run *request* models use `FiniteFloat` on financial scalars.
- `FXForwardPosition.pair` and `FXOptionPosition.pair` must be a 6-letter ISO pair (normalized to uppercase).
- No route, DTO name, or response schema changes. OpenAPI field types remain `number`; validation is runtime.

## Numerical conventions
- Units: unchanged (existing decimals, relative shocks, bp fields).
- Sign convention: unchanged (signed quantity/notional still allowed; finiteness only).
- Day count/calendar if relevant: N/A
- Tolerances/reference: `math.isfinite`; no magnitude policy.

## Tests added/updated

- `test_equity_price_negative_inf_raises_validation_error` — domain construction rejects -Inf price
- `test_maturity_years_inf_raises_even_when_gt_zero_would_pass` — `Field(gt=0)` + Inf is rejected
- `test_invalid_fx_pair_shape_raises_validation_error` — malformed FX pair rejected
- `test_market_snapshot_rejects_non_finite_spot` — snapshot float maps reject NaN
- `test_var_endpoint_rejects_non_finite_json_price` — POST `/api/v1/risk/var` with JSON `NaN` / `Infinity` / `-Infinity` returns 422
- `test_sample_and_demo_portfolios_still_validate` — SAMPLE / DEMO books still construct

No R0.2-A tests were edited.

## Known limitations / risks
- Magnitude caps were not added (finiteness only, as requested).
- `backend/app/api/scenario_wire.py` `FactorShockWire.amount` is still an unconstrained float (file not in the allowed edit set). Formal typed-scenario posts can still accept non-finite shock amounts until a follow-up.
- `allow_inf_nan=False` is not set globally on response models; this task rejects non-finite *inputs*. Engine outputs that are NaN/Inf remain a separate sanitization concern (SEC-008 / R0.11.4).
- FX pair policy is shape-only (`^[A-Z]{6}$` after strip/upper). It does not interpret `USDEUR` vs `EURUSD` (QA-017 reversal semantics).
- FastAPI 422 serialization: Pydantic records the original field `input` in `exc.errors()`, and `errors.py` dumps that list via Starlette `JSONResponse` (`allow_nan=False`). Request models rewrite NaN/Inf to JSON-safe labels *before* field validation and raise `PydanticCustomError` (not `ValueError`) so the existing handler can return 422 without editing `errors.py`. A later errors-layer sanitizer would still be the durable fix.
