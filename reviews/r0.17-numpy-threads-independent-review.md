## Leftover copy / thread-spawn holes (claimed kernel API)

These are leftovers, not a flip to REQUEST CHANGES.

1. **Object `pnl()` still packs every call.** `eflat` / `sflat` list comps + `(ctypes.c_double * n)(*…)` remain. That is the documented object API, not `pnl_from_arrays`.
2. **`out is None` allocates `np.empty(n_s)` every call.** Output scratch, not an input pack. Caller `out` skips it; tests lock that pointer.
3. **1×S with S ≥ 4096 still constructs the stdlib pool** when `workers > 1`. Predicate is `E×S < 4096`, not `n_exposures == 1`. A 1×4096 (or 1×5000) Historical-shaped book is parallel. No C++/pytest case at the 4095 / 4096 boundary.
4. **ctypes cannot see `kernel_last_used_workers_flag`.** The hook is a C++ `inline` function-local static, not a C ABI export. Python `test_native_tiny_workload_matches_python_with_many_threads` only checks 1×64 numbers at `THREADS=8`. Spawn absence is locked by `kernel_test.cpp` (compiled inside `test_cpp_kernel_compiles_and_executes`), not by ctypes.
5. **Large E×S still creates threads per call.** RF-017 allowed reuse-a-pool **or** serial-below-threshold. This slice took the threshold only. Claimed.
6. **`historical._pnl_via_scenario_kernel` still builds `Shock` lists and calls `pnl()`.** Slice scoped this out. That leftover is valid and is **not** a fail. It is why RF-017 must stay open.

## Findings

### 1. VALID — Minor — ctypes tiny-work test does not observe spawn

- Files: `backend/tests/test_native_kernel.py` L522–539; `backend/native/include/risk_kernel.hpp` L59–63
- What's wrong: The 1×64 / `THREADS=8` pytest only asserts `KERNEL_ABI_*` vs Python. A mutation that deleted `kernel_use_serial` from `portfolio_scenarios_flat_into` but left the C++ flag asserts would still fail `kernel_test.cpp`. A mutation that deleted **both** the gate and the flag asserts, keeping only pytest, would stay green on that file’s NumPy tests. The workers flag is not exported, so ctypes cannot fail-closed on spawn.
- Why it matters: The production ctypes path is what `pnl_from_arrays` / `pnl()` actually call. Spawn is proven only in the two-TU C++ binary.
- Suggested fix: Export a test-only C symbol, or keep the `kernel_test.cpp` flag asserts as the lock (they are, today). Optional: assert `1 * 4095` tiny and `1 * 4096` not tiny.

### 2. VALID — Minor — `out` writeable is documented, not checked

- Files: `backend/app/compute/kernel.py` L270–290
- What's wrong: Docstring requires writable C-contiguous `out`. The guard checks dtype, `c_contiguous`, `ndim == 1`, and size. `flags.writeable` is not tested. A read-only contiguous buffer is passed through to C, which writes it.
- Why it matters: Fail-closed on a bad `out` is incomplete. Not a pack/copy leftover.
- Suggested fix: Reject `not out_buf.flags.writeable` with `KERNEL_ERR_LENGTH` (or a dedicated error) the same way non-contiguous `out` is rejected.
