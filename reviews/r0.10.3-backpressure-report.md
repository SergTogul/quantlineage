## Summary
Picked **Option A**: HEAVY handlers refuse inline compute on the FastAPI request thread when a production-shaped deploy has an external worker (`RISKFORGE_EXTERNAL_WORKER=1`) or when `RISKFORGE_HEAVY_INLINE=0`. The two leftover request-thread sites are `POST /risk/summary?methodology=FULL_REVALUATION` and `POST /risk/dashboard`. Refusal is HTTP **400** with the existing envelope (`code=bad_request`, `message=Invalid request`) and `details.use=/risk/runs`. No job is enqueued — this is not a RiskRun platform. INTERACTIVE LINEAR / DELTA_GAMMA summary stays synchronous. Default (unset flags) still allows inline compute so local tests and in-process worker deploys keep working. Workload caps in `app.api.workload` were not changed. `execution_class.py` OpenAPI bijection is unchanged.

TDD: `tests/test_backpressure.py` was written first and failed 4 cases with `assert 200 == 400` (FULL_REVALUATION summary + dashboard still computed inline). Implementation then turned the suite green. LINEAR / DELTA_GAMMA already passed on RED.

## Known limitations / risks
- RF-015 is **not** closed. This slice only stops two leftover request-thread paths from running indefinitely under an external-worker / no-inline-heavy deploy.
- Other classified HEAVY routes (`/risk/var`, `/risk/es`, hierarchy, stress evaluate, what-if, contributors, …) still compute inline on the request thread even when `RISKFORGE_EXTERNAL_WORKER=1`.
- `POST /risk/var?methodology=FULL_REVALUATION` and `/risk/es` with FULL_REVALUATION are not gated (only summary + dashboard).
- Refusal does **not** enqueue a RiskRun. The client must `POST /risk/runs` itself. No 202 body / Location is returned because no job was accepted.
- Local / test default still allows inline dashboard compute (required by `test_dashboard_batch.py`).
- Worker `ThreadPoolExecutor(max_workers=2)` and workload caps were left as-is.
