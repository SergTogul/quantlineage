## Verdict: APPROVE

`value()` calls `terms_from_position`, dispatches on the terms type, and
stamps terms economics onto a working `*Position` before the existing
family builders. Equity cash PV uses `terms.quantity` directly. When
`market` is supplied, `_snapshot_marks_from_terms` overwrites leftover
DTO marks from snapshot keys taken off terms (symbol / pair / currency /
strike / maturity). Two cash equities that differ only in leftover DTO
`price` return the same snapshot PV (`10 * 100 = 1000`). Two options
that differ only in leftover DTO `spot` / `volatility` return the same
snapshot PV. Quantity and strike still move PV. Omitted `market=` still
prices from leftover DTO marks (documented leftover). `models.py`,
`interfaces/pricing.py`, and `instrument_terms.py` have empty diffs.
ABC `PricingEngine.value(self, position: Position, market: MarketSnapshot)`
is unchanged. Process lock, `_session`, `_maturity_date`, and family
builder signatures are unchanged vs HEAD. FINDINGS RF-001 remains
**IN PROGRESS**. DTO mark fields remain on `*Position`.

This slice is enough to treat **QuantLib `value()` as wired through
terms for economics identity, with snapshot mark authority when
`market` is supplied**. It is **not** enough to close RF-001:
compatibility `*Position` DTOs still embed marks, family builders still
consume a working `*Position` (not an `InstrumentTerms` object), and
omitted `market=` still uses those leftover marks.

## Findings

### 1. VALID — Minor — Terms-identity test is algebraic cash only

- File: `backend/tests/test_quantlib_terms_value.py`
  (`test_value_uses_terms_quantity_not_dto_when_terms_diverge`,
  `test_terms_quantity_and_strike_change_snapshot_pv`)
- What's wrong: The only committed test that splits terms from the DTO
  monkeypatches `terms_from_position` on cash equity and asserts
  `20 * snapshot_spot`. That path is
  `terms.quantity * working.price` — no QuantLib instrument. The
  quantity/strike test mutates DTO `quantity` / `strike`, so terms and
  the DTO stay aligned; it would still pass if `_option` read
  `position.strike` and `value()` never called terms.
- Why it matters: A regression that dropped `_economics_from_terms`
  (builders keep the original DTO) would not fail the committed suite.
  Production currently stamps terms onto the working copy; an
  independent option qty/strike monkeypatch (not committed) doubled QL
  PV and cheapened the call. Coverage hole, not a leftover mark leak.
- Suggested fix: Add one monkeypatch that changes
  `EuropeanOptionTerms.quantity` or `strike` while the DTO stays put
  and asserts `engine.value(..., market)` through `_option`. Defer;
  do not block this slice.
