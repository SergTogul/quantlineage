# R0.4.2-G — Historical + reverse use canonical Scenario

Status: **COMPLETE pending review** (2026-09-09)  
Owner: Stress & Scenario Engineer  
Related: RF-011 (**CLOSED**, named residuals), milestone § R0.4.2

## Goal

Stop historical replay from generating/applying `MarketScenario` as the
pipeline type, and make reverse-stress’s public answer carry the canonical
`Scenario` that was applied. Conversion helpers stay adapters, not a side
door.

## What changed

- `historical_market_scenarios` / panel equivalents yield `Scenario` with
  typed `FactorShock`. Aggregate expansion still runs against the **live**
  `MarketSnapshot`. Rate bp→decimal only via `shock_units`.
- `iter_*_shocked_snapshots` apply via `apply_scenario`.
- `MarketScenario` / `FactorChange` remain adapters (`market_scenario_from_*`,
  `apply_market_scenario`, `scenario_to_market_scenario`).
- `ReverseStressResult.scenario` is the applied canonical `Scenario` (zero,
  bound, or converged). HTTP JSON projects as ScenarioWire. `required_shock`
  wire units unchanged. Search stays one-factor-family binary search.
- R0.4.2-F independent review stamped **APPROVE** in FINDINGS/milestone.

## Explicitly unchanged

- Deprecated StressScenario HTTP POST routes (adapters only).
- Reverse `required_shock` units (equity/vol/fx relative; rates bp).
- Demo snapshot ids, VaR numbers.
- Nested MarketSnapshot Pydantic rewrite; RF-012 ladders; RF-013 versioning.

## RF-011 disposition

**CLOSED** — historical, stress, custom, reverse, persistence, and API share
`Scenario` + `FactorShock` as the stored/apply model.

Named residuals (not blocking close):

- Deprecated StressScenario HTTP POSTs.
- `MarketScenario` / `FactorChange` adapter (like StressScenario).
- Reverse search remains one-factor-family magnitudes.
- Flat dict `MarketSnapshot` storage (typed views already wrap it).
