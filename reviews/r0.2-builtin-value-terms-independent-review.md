`value()` caller now passes `working`. FINDINGS RF-001 remains
**IN PROGRESS**. DTO mark fields remain on `*Position`.

This slice is enough to treat **Builtin `value()` as wired through
terms for economics identity, with snapshot mark authority when
`market` is supplied**. It is **not** enough to close RF-001:
compatibility `*Position` DTOs still embed marks, family builders still
consume a working `*Position` (not an `InstrumentTerms` object),
omitted `market=` still uses those leftover marks, and leftover
`duration` on swap PV / bond dv01 is still the DTO field (not a
snapshot mark).

  (`test_value_uses_terms_quantity_not_dto_when_terms_diverge`,

  Production currently stamps terms onto the working copy; an

  leak.

  Defer; do not block this slice.

## InstrumentTerms vs RF-001

`value()` to terms without stripping DTO marks or changing the ABC.
`value()` now projects through `terms_from_position` and, when
`market` is supplied, refuses leftover DTO `price` / `spot` / vol /
yield / swap-rate as mark authority.

the target trade contract and removal of embedded marks from
`*Position`. Family builders still take a working `*Position` whose
field names include `price` / `spot` / `volatility` / `yield_rate`.
Omitted `market=` still reads those leftover marks. Leftover
`duration` is not on `BondTerms` / `SwapTerms` and is not stamped
from the snapshot, so swap PV and bond dv01 still move with the DTO
duration field. That is why RF-001 must stay open.

FINDINGS remaining text still says Builtin uses DTO marks. The
omit-`market=` half is still true. The explicit-snapshot half is now
stale for spots/vols/rates/quotes. Stale remaining-text is not a
close of RF-001. This review did not edit `FINDINGS.md`.

**Treat Builtin `value()` terms wiring as done. Do not close RF-001.**
