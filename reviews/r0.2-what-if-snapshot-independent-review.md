## Findings

### 1. VALID — Minor — Modify snapshot identity is not in the suite

- Files: `backend/tests/test_market_authority.py`, `backend/tests/test_what_if.py`
- What's wrong: The identity test covers add only. Remove has a numeric helper
  against the base SAMPLE snapshot. Modify is tested only at
  `apply_what_if_changes` (quantity rewrite), not through `what_if` with an
  injected provider.
- Why it matters: SAMPLE modify keeps the demo position-id set, so
  `_matching_demo_id` would still bind `demo:global-macro` if after-book
  re-inferred. A SAMPLE modify number test would not catch omitted `market=`.
  Production code does not branch on operation; I probed modify and it reuses
  the injected object. This is a coverage gap, not an open threading bug.
- Suggested fix: Parametrize the existing identity test over add / remove /
  modify (keep `scenarios=[]` so shocked copies do not break `is`).

### 2. VALID — Minor — Direct helpers still infer when `market` is omitted

- Files: `backend/app/risk/incremental_var.py`, `backend/app/risk/historical.py`
- What's wrong: `incremental_var` / `what_if_analysis` / `_calculate` take
  optional `market`. Omit it and each book calls `demo_market_snapshot`.
  `_calculate`'s non-`HistoricalRiskEngine` branch never forwards `market`.
- Why it matters: The production API is `service.what_if` → `what_if_analysis`
  with a resolved snapshot. Empty-book add in
  `test_zero_portfolio_add_trade_incremental_equals_standalone_var` still
  depends on the fallback (an empty base snapshot has no spots). That is the
  limitation the implementer listed. It is not a service-path defect.
- Suggested fix: Keep the fallback at the demo boundary. If a later slice
  wants fail-closed helpers, require `market` on `what_if_analysis` and give
  empty-book add an explicit overlay snapshot.

## Items checked and not findings

- Hunt “stress still re-snapshots after-book”: false on the what-if path.
  `StressEngine` still defaults to `DemoAggregateMarketDataProvider` when
  `market is None` (`evaluate`, `PortfolioService.stresses`). Those callers
  are outside this leftover. What-if stress P&L now uses the **portfolio**
  snapshot rather than the aggregate demo twin; that is the one-snapshot
  rule, not a leftover re-infer.
- Hunt “factor engine ignores market”: false. `calculate_typed` prices with
  the supplied object.
- `shocked_value` infers a one-trade adapter snapshot only when `market is
  None`. `StressEngine.run` passes the threaded market.
- Identity test uses `scenarios=[]` so `is snapshot` is not polluted by
  `shock_snapshot` copies. SAMPLE add uses default scenarios and would raise
  if after-book stress re-resolved. FULL_REVALUATION also derives historical
  snaps from the same base (`provider.calls == 1`); `is` is the wrong lock
  for that methodology.
- Adding a symbol absent from the base snapshot (`AAPL` on SAMPLE) raises
  `MissingMarketDataError` for `equity_spots[AAPL]`. That is R0.2 authority,
  not a threading miss. This leftover does not add a what-if mark overlay.
- `test_what_if_remove_matches_apply_helper` no longer calls
  `summary(after_book)` (which would resolve a new snapshot from the mutated
  set). It prices the after-book on the base SAMPLE snapshot.
- API `POST /risk/what-if` goes through `service.what_if`. Add-trade 200 in
  `test_what_if_api_add_trade`.
- Parallel vol-authority edits in `test_market_authority.py` / `pricing/**`
  were not scored.
