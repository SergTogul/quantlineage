### Minor

### 1. VALID — Minor — `_execute` rebuilds spec from the request blob only; first-class columns are not the execute source of truth

- What I observed: after enqueue, columns hold the resolved identity, but `_execute` calls `resolve_run_spec(header.request, …)` and never reads `header.historical_dataset_id`. Probe: enqueue with synthetic id → columns=`synthetic-historical-factors`; resolving an emptied request against the process demo engine yields `demo-historical-factors` (`MINOR2_DRIFT True`).
- Why it matters: R0.8.1 made columns first-class for reproducibility; execute still trusts the blob. Create path keeps them aligned today; claim/external rows or partial blobs can drift. Not a CSV silent-ignore regression.
- Suggested fix: resolve/rebind from persisted columns (or require request id to match columns and 400/FAILED on mismatch). Defer to R0.8.5 if product keeps request-as-source for this slice.
