# R0.2 Bond / Swap / IR Snapshot Authority Independent Review

Slice: families C–F — when `market is not None`, bonds, swaps, IR futures,
caps/floors, and swaptions require snapshot curve / `key_rates` /
`rates[<ccy>]` (discount or par), projection (`projection_rates` /
`rates` last scalar, or a projection curve) for IR-future and IR-option
forwards, `ir_future_quotes[<ccy>]` for STIR, and `ir_vols[<ccy>]` (or a
usable `vol_surfaces[<ccy>]` quote) for cap/floor/swaption; missing keys
raise `MissingMarketDataError`. `market is None` still uses trade-local
marks (compatibility; not scored for REQUEST CHANGES).
Workspace: uncommitted work on `r0-core-remediation` vs HEAD.
Implementer report: `reviews/r0.2-rates-ir-report.md` (claims, not proof).
Production files were not modified by this review. Index, HEAD, and
branch were not mutated. RF-001 was not closed.

## Verdict: APPROVE

Both pricers fail closed on a supplied snapshot that omits the USD rate
(bond/swap/IR discount), the IR-future forward (`projection_rates[USD]`
when `rates` is also empty), `ir_future_quotes[USD]`, or IR option vol
(no usable surface and no `ir_vols[USD]`). They still price from
trade-local `yield_rate` / `market_swap_rate` / `quoted_rate` /
`forward_rate` / `forward_swap_rate` / `discount_rate` / `volatility`
when `market is None`. QuantLib consumes overlayed marks, not the
caller’s original fields. I verified that in source and at runtime,
including in-memory helper restores. Canned `rates-macro` demo and
aggregate snapshots seed `ir_future_quotes["USD"]=0.042`; SAMPLE
`fut-ed` prices against both.

No leftover `rates.get(ccy, position.yield_rate / market_swap_rate)`,
`ir_future_quotes.get(..., position.quoted_rate)`, or
`ir_vols.get(..., position.volatility)` remains on the supplied-market
`PricingEngine.value` path in `builtin.py`, `quantlib.py` overlay,
`curve_rates.py` required helpers, or `surface_vol.py`. Residuals are
overlay-gated `continuous_zero(..., fallback=p.*)` inside QuantLib
cap/swaption components, Builtin surface moneyness still passing the
trade forward, unused `discount_factor(..., fallback_yield=)`, helper
duplication, and error-shape notes. Terms split and hierarchy/stress
omitted-`market=` inference were not scored.

## Attack results

1. **`rates.get(ccy, position.yield_rate / market_swap_rate)`.** Gone from
   both pricers on the supplied-market `value` path. Builtin swap uses
   `required_continuous_zero`; bond scalar path does too after
   `discount_factor` returns `None` (no curve). QuantLib overlay does
   the same before `_bond` / `_swap` read `p.yield_rate` /
   `p.market_swap_rate`. Pre-change `.get` / `continuous_zero(...,
   fallback=)` is in the HEAD diff.
2. **IR future `quoted_rate` / `forward_rate` from the position.** Gone
   on `value`. Builtin calls `required_ir_future_quote` and
   `required_continuous_zero(..., prefer_projection=True)`. QuantLib
   overlay writes both fields before `_ir_future` reads the copy.
   Empty quotes raise; empty projection+rates raise.
3. **Cap/floor/swaption `position.volatility` / discount / forward
   trade marks.** Gone on `value` for missing keys. Builtin uses
   `required_ir_option_vol` and `required_continuous_zero`. QuantLib
   overlay writes vol + rates before the session. Empty / wrong-ccy
   `ir_vols` raise. See leftovers for overlay-gated
   `continuous_zero(..., fallback=p.*)` and Builtin surface moneyness.
4. **One engine fail-closed, the other leftover.** Not found on
   `value()`. Overlay raises before the QuantLib session if a required
   rates/IR key is absent. `_curve_handle(..., flat_rate=p.yield_rate)`
   and `_ir_future` field reads see the overlayed snapshot marks.
5. **Tests only Builtin / only happy path; missing-key cases don’t
   raise.** Not found for behavior. Builtin has bond/swap rate,
   IR-future forward+quote, and IR-option discount/forward/vol cases
   that call `value` and assert `factor_key`. QuantLib tests cover
   bond/swap rate, IR-future quote, and IR-option vol. Missing
   QL-dedicated future-forward and IR-option discount/forward tests
   are a coverage gap; those paths were probed and raise the same keys.
6. **Happy-path tolerances weakened.** Not found. See criterion 9.
7. **RF-001 marked CLOSED.** Not found.
8. **`ir_vols` / `ir_future_quotes` silently unused.** Not found.
   `required_ir_option_vol` reads `market.ir_vols[name]`;
   `required_ir_future_quote` reads `market.ir_future_quotes[currency]`.
   Changing the quote from `0.042` to `0.050` and vol from `0.20` to
   `0.30` moved Builtin and QuantLib PVs. Both maps enter
   `content_hash`.

## Findings

### 1. VALID — Minor — QuantLib IR-option components still take a trade-mark fallback

- File: `backend/app/pricing/quantlib.py`
- What's wrong: `_cap_floor_components` / `_swaption_components` still
  call `continuous_zero(..., fallback=p.*)` and read `p.volatility`
  directly. Overlay in `value()` is fail-closed; the leftover is live
  if those methods are called without overlay.
- Why it matters: Same overlay-debt shape as approved FX. Not a
  current `value()` bypass. A later “stop copying marks onto the
  position” cleanup can re-open cap/swaption if these call sites are
  left as the authority.
- Suggested fix: Resolve with `required_continuous_zero` /
  `required_ir_option_vol` inside the components (match Builtin), then
  stop overlaying IR marks.

### 2. VALID — Minor — Builtin IR surface moneyness still uses the trade forward

- File: `backend/app/pricing/builtin.py`
- What's wrong: On a supplied market, vol lookup passes
  `forward=p.forward_rate` / `p.forward_swap_rate` into
  `required_ir_option_vol` while the Black forward comes from
  `required_continuous_zero`. Equity/FX already pass the snapshot
  spot. QuantLib overlay already passes the resolved snapshot forward.
- Why it matters: Scalar `ir_vols` (the slice’s new map) ignores
  moneyness. A `vol_surfaces[USD]` book can pick a different node
  than QuantLib. Not a missing-key `.get` leftover; no IR-surface
  authority test locks it.
- Suggested fix: Resolve snapshot forward first; pass that into
  `required_ir_option_vol`. Add a surface case next to the `ir_vols`
  missing-key tests.

### 3. VALID — Minor — QuantLib missing-key tests omit forward/discount twins

- File: `backend/tests/test_quantlib_pricing.py`
- What's wrong: Implementer report claimed matching QuantLib overlay
  cases. QL tests cover bond/swap rate, STIR quote, and IR vol.
  Builtin-only: IR-future forward, IR-option discount, IR-option
  forward.
- Why it matters: Restoring overlay `continuous_zero(...,
  fallback=position.forward_rate)` for those three keys would stay
  green on the QL file. Runtime probe today raises. Same class as
  prior “missing-key cases fail; happy-path alone would not.”
- Suggested fix: Copy the three Builtin parametrizations onto
  `engine.value`.

### 4. VALID — Minor — `MissingMarketDataError` still names only the factor key

- File: `backend/app/market/demo_snapshot.py` (unchanged this slice)
- What's wrong: Brief §3 asked the typed error to name trade id **and**
  factor key. Call sites still pass only `rates[USD]` /
  `projection_rates[USD]` / `ir_future_quotes[USD]` / `ir_vols[USD]`.
- Why it matters: Same shape as approved R0.2 equity/FX slices. Logs
  for a multi-ccy book will not say which trade failed. Not a silent
  fallback.
- Suggested fix: Thread `position.id` into the error when the helpers
  are unified.
