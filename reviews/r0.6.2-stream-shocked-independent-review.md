## Findings

### 1. VALID — Minor — Production-loop pytest is source-token grep and would stay green on `list(iter_...)`

- Files: `backend/tests/test_iter_shocked_snapshots.py` L147–158
- What's wrong: `test_full_reval_production_loops_use_iterator_not_list` only asserts that `inspect.getsource` contains `iter_historical_shocked_snapshots` and that a lookbehind regex does not see a bare `historical_shocked_snapshots`. A later consumer that wrote `shocked = list(iter_historical_shocked_snapshots(...)); for snap in shocked:` would still pass. The companion type tests prove the **generator functions** return generators; they do not prove the **consumers** avoid materializing. The numerical identity test would also stay green on a list wrap.
- Why it matters: This is the same comment/token class as the R0.6.1 bench Minor — the on-disk loops are real (bytecode: `GET_ITER`/`FOR_ITER`, no `list()` of the iterator; frame holds no snapshot list). A leftover-style echo that kept the iterator name would not fail this suite.
- Suggested fix: In pytest, fail if the production source matches `list(` + `iter_historical_shocked_snapshots`, or disassemble and forbid `LIST`/`CALL list` on that iterator. Keep the type tests on the generators.
