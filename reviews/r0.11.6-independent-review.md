## Findings

### 1. VALID — Important — Frontend non-root is untested

- Files: `backend/tests/test_container_hardening.py`, `frontend/Dockerfile`,
  `frontend/nginx.conf`
- What's wrong: Acc 3 requires the frontend image to drop to non-root.
  The new tests pin `"latest"`, `npm ci`, and backend `USER` only.
  `test_frontend_dockerfile_uses_npm_ci` is a substring check on the whole
  file. Deleting `USER nginx`, moving it into the `build` stage only, or
  removing `frontend/nginx.conf` (pid/temp, no `user` directive) does not
  fail pytest.
- Why it matters: Docker daemon is missing, so these tests are the slice’s
  only gate. Frontend privilege drop is not a one-liner: official
  `nginx:alpine` as `USER nginx` plus listen 80 is unsafe without the custom
  conf. Backend `USER` cannot regress unnoticed; frontend `USER` can.
  Acc 5 omitted this mutation; Acc 3 did not omit the behavior.
- Suggested fix: Parse the **final** stage of `frontend/Dockerfile` (after
  the last `FROM`) and assert its last `USER` is not root/`0`. Assert
  `nginx.conf` sets `pid` and the temp paths under a writable location
  (`/tmp` is fine) and does not contain a `user` directive. A comment
  containing `npm ci` / `USER nginx` must not satisfy the tests.

### 2. VALID — Minor — `COPY . .` can replace the `npm ci` tree

- File: `frontend/Dockerfile` (pre-existing `COPY . .`; no `.dockerignore`
  added). This workspace has `frontend/node_modules`.
- What's wrong: Build context is `./frontend`. After `RUN npm ci`, `COPY . .`
  copies a host `node_modules` (Darwin binaries here) over the Alpine install.
  `npm run build` may then use the host tree, not the `npm ci` layer.
- Why it matters: Undermines the determinism claim of Acc 2 on the common
  local `docker compose build` path. A clean CI checkout without
  `node_modules` is fine. The same `COPY` existed before this slice.
- Suggested fix: Add `frontend/.dockerignore` with at least `node_modules`,
  `dist`, and local junk. Optionally `COPY --chown=nginx:nginx` in the
  final stage to drop the extra `chown` layer.

### 3. VALID — Minor — `npm ci` assertion does not reject a surviving `npm install`

- File: `backend/tests/test_container_hardening.py`
- What's wrong: `assert "npm ci" in text` passes for
  `RUN npm ci \|\| npm install`, a comment that mentions `npm ci`, or
  `RUN npm install` plus a later unused `npm ci` string.
- Why it matters: The exact Acc 5 restoration (replace `npm ci` with
  `npm install`) does fail. Weaker cousins do not.
- Suggested fix: Require a `RUN` line whose install command is `npm ci`
  and assert no `RUN` line invokes `npm install`.
