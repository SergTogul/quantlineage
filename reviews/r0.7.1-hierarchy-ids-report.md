## Summary
Every `HierarchyNode` returned by `HierarchyEngine.build` and `risk_at` now has a
deterministic `id` covering all six levels. IDs are unique within a
multi-desk / multi-book tree and identical across two builds of the same book.

The id scheme is the one `portfolio_at` already used for **sub-portfolio**
`Portfolio.id` values. A shared helper `hierarchy_node_id` in
`hierarchy_placement.py` is the single source; `portfolio_at` now calls it
instead of inlining the same strings. `portfolio_at` filtering, naming, and
desk/strategy inheritance are unchanged.

`path` is still the slash-separated display breadcrumb
(`{firm}/{portfolio.id}/{desk}/{strategy}/{book}/{trade_id}`). `id` is the
stable address. They differ because `path` is a human-readable tree location
that includes firm and portfolio labels at every level, while `id` matches
the existing sub-portfolio keys so later limits/drilldown can name the same
node:

| Level | `id` (aligned with `portfolio_at`) | `path` example |
|---|---|---|
| firm | `firm:{firm}` | `Acme Capital` |
| portfolio | `{portfolio.id}` | `Acme Capital/multi-desk` |
| desk | `desk:{desk}` | `Acme Capital/multi-desk/Rates Desk` |
| strategy | `strategy:{desk}/{strategy}` | `Acme Capital/multi-desk/Rates Desk/Carry` |
| book | `book:{desk}/{strategy}/{book}` | `Acme Capital/multi-desk/Rates Desk/Carry/Cash A` |
| trade | `{trade_id}` | `Acme Capital/multi-desk/Rates Desk/Carry/Cash A/eq-a` |

`HierarchyNode.id` defaults to `""` so older payloads and OpenAPI clients that
omit the field still parse. `HierarchyEngine` always populates it. The only
`HierarchyNode(` construction site is `_node`.

This slice does **not** stop per-node full recomputation. VaR/ES numbers and
additive 1e-9 reconciliation are unchanged. RF-008 stays open.

## Known limitations / risks
- **Per-node full recomputation remains.** `HierarchyEngine._node` still
  recalculates VaR, ES, stress, and limits on each sub-portfolio. That is
  R0.7.2 / R0.7.3. RF-008 is not closed.
- After CHANGES REQUESTED: every level is prefixed (`portfolio:…`,
  `trade:{desk}/{strategy}/{book}/{trade_id}`). Empty labels stay empty
  segments; ``/`` in a label is ``%2F``. `portfolio.id == trade.id` and
  `""` vs `"trade"` no longer share an id.
- Desk `id` is still `desk:{desk}` without a portfolio prefix. Unique in the
  current Firm → single Portfolio tree. A future multi-portfolio firm tree
  with the same desk name in two portfolios would collide unless the scheme
  is extended.
- `HierarchyNode.id` default `""` is only for payload compatibility; an
  unpopulated node is not a valid engine result.
