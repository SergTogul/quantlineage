## Owner

## Summary
Production hierarchy, stress, and reverse-stress entry points no longer infer a
`MarketSnapshot` from the book when `market` is omitted. They raise
`ValueError("production risk calculation requires an explicit MarketSnapshot")`
via `require_explicit_market` and do not call `demo_market_snapshot` or
`DemoAggregateMarketDataProvider.snapshot`.

Covered methods:

- `HierarchyEngine.build` / `risk_at`
- `StressEngine.run` / `evaluate` / `contributions`
- `ScenarioComparisonEngine.compare`
- `ReverseStressEngine.solve`
- `MultiFactorReverseStressEngine.solve`

`PortfolioService` was not changed. It already resolves one root snapshot and
threads it into hierarchy, stress, reverse, reverse-multi, compare, and
dashboard paths.

`demo_market_snapshot` remains for named demo/sample helpers and tests that opt
in. Signatures stay `market: MarketSnapshot | None = None` so the failure is a
domain `ValueError` (same type and “explicit MarketSnapshot” wording as VaR/ES),
not a `TypeError`.

TDD: new omit-`market=` tests failed first (`DID NOT RAISE ValueError`) while
engines still inferred demo marks. After fail-closed, those tests passed and
callers/tests that omitted `market=` were updated to pass fixtures or
`demo_market_snapshot` in tests only.
