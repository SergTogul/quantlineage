## Item 1 — Incomplete snapshot must not price from trade-local equity marks

**Status: FIXED.** No remaining Critical/Important.

`BuiltinPricingEngine.value` requires `market.equity_spots[symbol]` when
`market is not None` and raises `MissingMarketDataError` on `KeyError`. The
QuantLib overlay does the same before copying `price` onto the trade. `market
is None` still uses `position.price` (9990.0 for the AUTH probe). Other
families' `.get(k, position.mark)` fallbacks were not re-opened.

Runtime probes (`EquityPosition(AUTH, qty=10, price=999)`):

| Call | Empty snapshot | SPY-only snapshot | `market=None` |
|---|---|---|---|
| Builtin `value` | `MissingMarketDataError` | `MissingMarketDataError` | `9990.0` |
| QuantLib `value` | `MissingMarketDataError` | `MissingMarketDataError` | `9990.0` |
| Cached (Builtin inner) | `MissingMarketDataError` | `MissingMarketDataError` | n/a (cache requires market) |
| Historical LINEAR | `MissingMarketDataError` | `MissingMarketDataError` | n/a |
| Historical FULL | `MissingMarketDataError` | — | n/a |
| VaRAnalytics LINEAR | `MissingMarketDataError` | — | n/a |
| `shocked_value(..., empty)` | `MissingMarketDataError` | — | n/a |

QuantLib with `equity_spots={"AUTH": 101}` returned `1010.0`.

Mutation: restoring `equity_spots.get(symbol, position.price)` on Builtin
returned `9990.0` for both empty and SPY-only. That would fail
`test_missing_equity_spot_raises_when_market_is_supplied` and
`test_linear_var_raises_when_supplied_snapshot_omits_equity_spot`.

Residual (Minor, not blocking): `test_market_authority.py` never instantiates
QuantLib. A QuantLib-only restore of `.get` would not fail that file. I
verified the overlay at runtime anyway. `test_quantlib_pricing.py` also has no
`MissingMarketDataError` case.

## Item 2 — Demo matcher must not bind an incomplete canned snapshot

**Status: FIXED.** No remaining Critical/Important.

`_matching_demo_id` binds a canned snapshot only when `portfolio.id` is a
known demo **and** the position-id set equals that demo's set. Subset,
superset, new id, and same demo id with extra trades all return `None` and
fall through to `DemoSampleMarksSnapshotAdapter`.

Required probe — `SAMPLE_PORTFOLIO` plus AAPL equity (`id=eq-aapl-extra`,
`price=1000`):

| Book id | `_matching_demo_id` | `demo_market_snapshot` |
|---|---|---|
| `custom-superset` | `None` | `ConflictingSampleMarkError` on `rates[USD]` |
| `global-macro` (diverged) | `None` | same conflict |

That is fail-closed, not the canned `demo:global-macro` spots-only snapshot
(`NVDA`/`SPY` only). Extra AAPL is not silently valued from the trade against
that canned object.

Additional probes (not required, used to hunt leftovers):

- Exact `SAMPLE_PORTFOLIO` / `equity-vol` / `rates-macro` still bind their
  canned snapshots.
- First two SAMPLE positions, new id or `id=global-macro`: matcher `None`;
  adapter snapshot `demo_sample_marks` with `NVDA`/`SPY`.
- `EQUITY_VOL + RATES_MACRO` (new id or `id=equity-vol`): matcher `None`;
  adapter raises on conflicting USD marks.
- `EQUITY_VOL + AAPL`: matcher `None`; adapter raises on conflicting SPY vols.

The old subset/superset matcher would still bind `global-macro` for both
required book ids and return `demo:global-macro` without AAPL. The current
test then hits `assert snapshot.id != "demo:global-macro"` /
`assert "AAPL" in snapshot.equity_spots` and would fail. Because the adapter
raises first on SAMPLE+AAPL, the test's `except` path is the one that runs
today; that is allowed fail-closed, not a silent canned bind.

Residual (Minor, not blocking): the `"AAPL" in snapshot.equity_spots` branch
is unreachable for this mixed-USD book. The test still fails a matcher
regression because the old matcher returns a snapshot instead of raising.

## Item 4 — `contributors` / `compare_var_methodologies` must use the service snapshot

**Status: FIXED.** No remaining Critical/Important.

Both methods now call `self.market_snapshot(portfolio)` and pass that object
through, the same way as `var_report`.

- `contributors` → `self.var_engine.report(..., market=self.market_snapshot(portfolio))`
- `compare_var_methodologies` → `compare_methodologies(..., market=self.market_snapshot(portfolio))`
- `compare_methodologies` forwards `market` into `HistoricalRiskEngine.calculate`

Probe: injected `MarketSnapshot(id="service", equity_spots={"AUTH": 105})`.

| Entry point | Provider calls (cumulative) | All `pricing.value` markets `is` injected snap | Result |
|---|---|---|---|
| `summary` LINEAR | 1 | yes | `market_value=1050` |
| `contributors` | 2 | yes | priced against 105, not 999 |
| `compare` LINEAR | 3 | yes | same snapshot |
| `var_report` LINEAR | 4 | yes | same snapshot |

Omitting `market=` (old contributors style) made `VaRAnalytics.report` infer
`demo_sample_marks` and never touch `service.market_data`.
`test_portfolio_service_passes_resolved_snapshot_to_contributors_and_compare`
would fail (`provider.calls` stays 0; `market is snapshot` is false).

`what_if` / engine `market=None` inference were not required for this
re-review (Finding 5 deferred).

### M2. VALID — Minor — SAMPLE+AAPL success assertions are dead code

- File: `backend/tests/test_market_authority.py`
  (`test_sample_plus_extra_aapl_does_not_bind_incomplete_canned_snapshot`)
- What's wrong: SAMPLE+AAPL always raises `ConflictingSampleMarkError` from
  mixed USD sample marks, so the `AAPL in equity_spots` asserts never run.
- Why it is not Important: Fail-closed satisfies the item. Restoring
  subset/superset matching returns a canned snapshot and fails those asserts.
- Suggested fix: Add a no-conflict book (equities only + extra AAPL) that
  must resolve with `AAPL` in spots, and keep SAMPLE+AAPL as the fail-closed
  case.
