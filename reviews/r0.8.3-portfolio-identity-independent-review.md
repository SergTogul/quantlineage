### 1. VALID — Minor — Submit tests lock storage, not the book queued for execute

- What I observed: both persist submit tests use `execute=False` and assert `SqlAlchemyPortfolioRepository.get(...)`. They never read `worker._portfolios[view.id]` and never complete a run against the posted-vs-stored book. `_book_for_run` that returned the POST body and did **not** call `save` would leave the stored row alone; those tests would stay green while in-process `_execute` used the attacker positions (`_portfolios` is checked before `_load_portfolio`).
- Why it matters: the slice’s policy is attach-the-stored-book for calculate, not only “do not upsert.” Storage overwrite is locked. Calculate-attach is implied by the same helper, not proven.
- Suggested fix: after submit, assert the cached book (or `execute=True` on a file SQLite factory, then assert the run used stored quantity/symbol). Not required to APPROVE; restoring `save(posted)` already fails the existing `get` assertions.
