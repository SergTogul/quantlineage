## Summary

QuantLib `Settings.evaluationDate` and `IndexManager` fixing histories are process-global. The adapter no longer serializes them with a per-instance `RLock`.

Process ownership:

- Module-level `_QL_PROCESS_LOCK` is created at import, outside instance `__init__`.
- Every `QuantLibPricingEngine` binds `self._lock` to that same object (`QuantLibPricingEngine._process_lock is _QL_PROCESS_LOCK`).
- Two engine instances therefore share one lock. `_session` is the only QuantLib ownership boundary.
- Outermost session enter/exit clears `IndexManager` histories (QuantLib 1.43 Python exposes `histories` / `clearHistories` only). Nested re-entrant sessions on the same thread increment `_QL_SESSION_DEPTH` and do not clear mid-valuation.
- `value()` parses snapshot `as_of` when it is an ISO calendar date and uses that as the session evaluation date (Settings + `self.evaluation_date` for the duration of the session). Labels such as `current` and `t0` fall back to the engine date so existing goldens stay on their explicit `evaluation_date`.

Two engine instances now share one lock: **yes**.

## Known limitations / risks

- `MarketSnapshot.as_of` is still an unconstrained string. Only ISO dates are applied; demo labels stay on the engine date.
- IndexManager snapshot/restore is not available in QuantLib 1.43 Python (`getHistory` / `setHistory` are not bound). The session **clears** histories on outermost enter/exit rather than restoring a prior TimeSeries.
- In-process QuantLib calls are fully serialized. Parallel full revaluation remains a process-partition problem (R0.3.5 / RF-007).
- RF-001 family (FX/bond fallbacks, omitted `market=`) was not touched.

## Addendum — factory cache as-of key (Important #1)

Independent review reproduced a leftover as-of bypass: `create_pricing_engine()` wraps QuantLib in `CachedPricingEngine`, and `market_cache_key()` hashed marks only. After R0.3.4 made parseable ISO `as_of` drive QuantLib evaluation date, two ISO dates with the same marks shared one valuation key. Factory path on the 2Y USDLibor payer swap (`rates={"USD": 0.04}`) returned the 2018 PV (`~102212.08`) for `as_of=2024-06-14` after a 2018 miss.

**Fix:** `market_cache_key` now appends `|as_of:YYYY-MM-DD` when snapshot `as_of` is a parseable ISO date or `date`. Labels (`current`, `t0`, `later`) still omit as-of and stay equivalent (they use engine `evaluation_date`, already in `PricingConfiguration`). `id` remains excluded. `MarketSnapshot.content_hash()` is unchanged (marks-only).

RF-002 stays **IN PROGRESS**. Not done: typed `as_of` (R0.3.1), process-partitioned full reval (R0.3.5), Acc 5 sleep, nested-session tests, datetime-ISO parser.
