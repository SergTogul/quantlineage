entry equal to (or `endswith`) the required `127.0.0.1:<map>`. Dual
unbound host publishes, `worker` `8001:8001`, and a fourth service with
`ports:` stayed green.

Now: `published_port_violations` iterates every 2-space service body,
collects every `ports:` entry (inline list, block list, long-form
`host_ip`), and fails any parsed mapping whose `host_ip` is not
`127.0.0.1`. Required postgres / backend / frontend mappings must still
be present. Current `docker-compose.yml` yields `[]`.

In-memory mutations of the **on-disk** Compose text (expect FAIL unless
noted). Extra `debug` is inserted under `services:` (before `volumes:`),
not appended after the file — a tail append lands outside `services:`
and is not a real Compose publish.

## Finding 2 — Regex / `endswith` fallback — CLOSED

Original: body capture dropped the rest of a service after a blank
line; inline `[^\]]*` mangled `"[::]:…"`; `/tcp` and long-form
`host_ip` failed the suite while still being loopback; 
`entry.endswith(mapping)` treated `127.0.0.1:15432:5432` as satisfying
`5432:5432`.

Now: mappings are split into `host_ip` / `published` / `target`. The
required-mapping check is exact field equality, not a suffix. Unparsed
entries append a violation and do not count as loopback. `/tcp` is
stripped before the field split. Long-form block `host_ip` is accepted.

| Mutation | Helper result |
|---|---|
| `127.0.0.1:15432:5432` in place of postgres `5432:5432` | FAIL: `postgres: missing 127.0.0.1:5432:5432` (no false satisfy) |
| long-form `published: 15432` / `target: 5432` / `host_ip: 127.0.0.1` | FAIL: missing required mapping |
| `ports: […, "not-a-valid-port-mapping"]` | FAIL: `unparsed port entry` |
| `127.0.0.1:5432:5432/tcp` | PASS |
| long-form `target` / `published` / `host_ip: 127.0.0.1` | PASS |
| `"[::]:5432:5432"` | FAIL: host_ip is `::`, not 127.0.0.1 |
| blank line then unbound `5432:5432` | FAIL (ports still seen) |
| `localhost:5432:5432` | FAIL (not `127.0.0.1`) |
| container-only `5432` | FAIL (no host_ip) |

`test_wrong_host_port_does_not_satisfy_required_mapping`,
`test_unparsed_port_entry_fails_closed`,
`test_tcp_suffix_is_accepted_as_loopback`, and
`test_long_form_host_ip_is_accepted` lock those cases.
