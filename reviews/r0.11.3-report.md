# R0.11.3 Workload limits

## Task
R0.11.3 Workload limits (RF-014)

## Owner
Backend / API Engineer

## Summary
Added env-overridable HTTP workload caps so a client cannot submit pathological books or payloads. A FastAPI dependency (`enforce_workload_limits`) is registered on the app in `main.py` and therefore covers forbidden routers (`risk.py`, `limits.py`, `risk_runs.py`) without editing them. It rejects oversized `Content-Length` / raw bodies and, after JSON parse, walks `positions` / `scenarios` lists (nested portfolios included; a top-level JSON array is treated as a scenario list). Rejection is HTTP 413 with the existing `{code,message,details}` envelope (`code=payload_too_large`) via `app.api.errors.error_payload`. Defaults: 500 positions, 50 scenarios, 1 MiB body. `SAMPLE_PORTFOLIO` still passes. Observation `le=5000` on `/risk/var/compare` is unchanged. Reverse-stress iteration defaults were not touched. Auth was not added.

TDD: `tests/test_workload_limits.py` was written first and failed at collection (`ImportError: cannot import name 'workload'`). Implementation then turned the suite green.

## Known limitations / risks
- Caps inspect parsed JSON lists, not Pydantic models after route validation. Invalid JSON is left to the existing 422 handler.
- DI-supplied default scenario lists (e.g. `POST /risk/stress` / `evaluate` without a client `scenarios` array) are not capped; only request-body lists are.
- What-if `add` that would grow the book past the cap after mutation is not checked; only `positions` lists present in the request are counted.
- If `Content-Length` is omitted or understated, the body is still fully buffered by Starlette before the actual-size check.
- Other observation query params were not capped (`risk.py` is forbidden). Compare remains `le=5000`.
- Queue depth / concurrency / auth are out of scope (R0.11.5 and later).
- `errors.py` has no 413 default code map; this slice sends a structured detail so the envelope code is `payload_too_large` rather than `http_413`.

### Summary
- `WorkloadBodyLimitMiddleware` is pure ASGI (not `BaseHTTPMiddleware`). Added last in `main.py` so it is **outermost**: it owns `receive` before `LegacyDeprecationMiddleware` and before FastAPI/Pydantic body parsing.
