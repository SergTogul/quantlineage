## Findings

### 1. VALID — Important — Current gate presents a copied Phase A snapshot as today's suite

- Files: `ROADMAP.md` (Current R0 verification), `reviews/r0.13.4-report.md`
- What's wrong: R0.13.4 / RF-020 require **current** results, not stale counts. This slice copied the R0 Baseline Verification table from earlier the same calendar day (commit `0085f4f` era: pre-insertion builtin 659, post-R0.1 QuantLib 688) and did not execute the matrix. HEAD is `34dbda5` after Phase B / R0.2 / R0.11 / R0.12 work. ROADMAP then says a 2026-09-02 **160 passed** figure “is a historical snapshot, not today's suite size,” which makes 659/688 the implied live size.
- Why it matters: RF-020’s residual is stale suite counts. Replacing an old number with another recorded number, then calling the new table “Current” and “today,” repeats the same failure mode with a better citation. Builtin collect on this workspace is **801** without the untracked workload file and **820** with it — not 659. I did not treat the implementer brief (“point at the recorded baseline”) as proof that a copy satisfies “current.”
- Suggested fix: Either (a) re-run the recorded commands on a stated SHA/tree and put those results in Current gate, or (b) retitle the block to the recorded Phase A baseline, state “not re-run,” and delete the phrase “today's suite size.” A pointer alone is not enough while the heading and the 160 contrast claim currency.

### 2. VALID — Important — 659 and 688 are shown as contemporaneous engine results

- Files: `ROADMAP.md` lines 15–16; contrast `reviews/REMEDIATION_MILESTONE.md` lines 34–41
- What's wrong: The milestone is explicit that 659 and 688 are **different suites at different times**. Current gate places them in one “current” table with no “Before new R0.1 test files” / “After R0.1.1–R0.1.6” notes. The QuantLib row also omits `RISKFORGE_PRICING_ENGINE=quantlib` (the recorded command sets both that and `RISKFORGE_REQUIRE_QUANTLIB=1`).
- Why it matters: A reader of Current gate will take “builtin 659, QuantLib 688, 0 skipped” as today's two-engine matrix. The 29-test delta is golden/CI-helper insertion, not QuantLib vs builtin on one tree. That is the conflation RF-020-style truthfulness has to prevent, even though the integers were not swapped or averaged.
- Suggested fix: Carry the milestone notes into the ROADMAP rows, or show one dated suite with both engines run on that same tree.

### 3. VALID — Minor — Current gate omits recorded lint/build/kernel-compile evidence

- Files: `ROADMAP.md` Current R0 verification table
- What's wrong: The recorded baseline includes ruff, mypy, frontend lint, frontend build, and native `g++` → `risk_kernel_ok`. R0.13.4 asks for reproducible **commands and** results. Current gate keeps a subset of pass counts and says commands live in the milestone file. Native compile is reduced to pytest **8 passed**.
- Why it matters: Someone who treats Current gate as the verification record will not see static analysis or the production build. The pointer is real; the table is not the matrix. This is incomplete recording, not a false pass.
- Suggested fix: Add the omitted rows as “recorded baseline, not re-run,” or state that the table is a subset and list the missing checks by name.
