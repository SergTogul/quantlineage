### Minor

### 1. VALID — Minor — `methodology` column does not override a conflicting request blob

- What I observed: `request_blob_for_execute` always overwrites `historical_dataset_id` / version / `as_of` / `calculation_config` from columns when set, but methodology only copies when `"methodology" not in req`. Probe: column `FULL_REVALUATION` + blob `DELTA_GAMMA` → execute blob keeps `DELTA_GAMMA` (`METH_COLUMN_OVERRIDES False`).
- Why it matters: asymmetric with the R0.8.5 column-as-truth hardening. Create/enqueue keep methodology aligned today; an external blob edit could diverge from the first-class column without fail-closed. Not the RF-009 historical-dataset root cause.
- Suggested fix: overwrite methodology from the column when set (same as dataset fields), or fail closed on blob≠column mismatch. Non-blocking for this APPROVE / RF-009 Lead close.
