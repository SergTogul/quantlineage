# Agent Handoff Template

## Task
R0.2 remaining-family cache identity (RF-001 terms projection)

## Owner
Quant Pricing Engineer

## Summary
`trade_cache_key` now hashes contractual economics only for every Position
family, matching the equity-family projection already in place. Bond, swap,
FX forward/option, IR future, cap/floor, and swaption no longer use
`legacy_position_v1`. Trade-local snapshot marks (`yield_rate`,
`market_swap_rate`, spots, vols, quoted/forward rates, discount/par rates)
and derived `duration` are dropped from the trade fingerprint. Quantity,
notional, strike, maturity, pay/receive, currency, and `fixed_rate` remain.
Unknown families raise `TypeError` instead of hashing a full payload.
Position DTOs and persistence models are unchanged. No new pricing library
or valuation formula was added.

## Public/interface changes
- No DTO, API, or snapshot schema change.
- `trade_cache_key` is fail-closed: every known family has an explicit
  `*_terms_v1` schema; unrecognized types raise
  `TypeError` (`no terms projection`).
- Family schemas and excluded marks:

  | Schema | Excluded (snapshot marks / derived) |
  |---|---|
  | `equity_terms_v1` | `price` (unchanged) |
  | `equity_future_terms_v1` | `spot`, `risk_free_rate`, `dividend_yield` (unchanged) |
  | `equity_option_terms_v1` | `spot`, `volatility`, `risk_free_rate`, `dividend_yield` (unchanged) |
  | `bond_terms_v1` | `yield_rate`, `duration` |
  | `swap_terms_v1` | `market_swap_rate`, `duration` |
  | `fx_forward_terms_v1` | `spot`, `domestic_rate`, `foreign_rate` |
  | `fx_option_terms_v1` | `spot`, `volatility`, `domestic_rate`, `foreign_rate` |
  | `ir_future_terms_v1` | `quoted_rate`, `forward_rate` |
  | `cap_floor_terms_v1` | `volatility`, `forward_rate`, `discount_rate` |
  | `swaption_terms_v1` | `volatility`, `forward_swap_rate`, `discount_rate` |

- Valuation cache prefix remains `v2`. Trade-key schema names already change
  the fingerprint for the newly migrated families.

## Numerical conventions
- Units: unchanged. This slice is cache identity only; Builtin/QuantLib PV
  and Greeks are not modified.
- Sign convention: unchanged.
- Day count/calendar if relevant: unchanged.
- Tolerances/reference: identity tests compare exact SHA-256 fingerprints.
  Changing a snapshot mark on the Position must leave the key equal;
  changing notional, strike, quantity, face, or `fixed_rate` must change it.

## Known limitations / risks
- This is cache identity only. Typed `InstrumentTerms` classes and removal of
  embedded marks from Position DTOs remain later RF-001 work.
- Builtin/QuantLib may still read trade-local marks when a snapshot is absent
  on compatibility paths; that is outside this slice.
- In-process cache entries computed under `legacy_position_v1` will miss after
  this change because family schema names changed. That is intended.
- Hierarchy/book metadata still participate in the economics dump (they are
  not snapshot marks).
