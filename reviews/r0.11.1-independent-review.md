## Findings

### 1. VALID — Important — Test allows additional non-loopback publishes

- Files: `backend/tests/test_compose_loopback.py` (`REQUIRED_PUBLISHES`,
  `test_compose_published_ports_bind_loopback` lines 49–59)
- What's wrong: The test only asks whether each of three services has
  *some* entry equal to (or `endswith`) the required `127.0.0.1:<map>`.
  It does not walk every service, and it does not reject other entries
  on the same `ports:` list. The implementer report says the test
  “parses `docker-compose.yml`.” The helper is a 2/4-space regex, not
  `yaml.safe_load`.
- Why it matters: Acc 4 is the regression net for SEC-004 / RF-014
  (“`docker compose up` does not expose the unauthenticated demo on a
  shared network”). I ran the same membership predicate the test uses:

  | Mutation | Test result | Host exposure |
  |---|---|---|
  | `ports: ["5432:5432"]` (named Acc 4) | FAIL | would bind all interfaces |
  | `ports: ["0.0.0.0:5432:5432"]` | FAIL | would bind all interfaces |
  | `ports: ["127.0.0.1:5432:5432", "15432:5432"]` | **PASS** | LAN on `:15432` |
  | `ports: ["127.0.0.1:5432:5432", "0.0.0.0:15432:5432"]` | **PASS** | LAN on `:15432` |
  | `worker` `ports: ["8001:8001"]` | **PASS** | LAN on `:8001` |
  | extra service `debug` `ports: ["5432:5433"]` | **PASS** | LAN on `:5432` |

  Same-host-port dual bind (`127.0.0.1:5432:5432` plus `5432:5432`)
  would likely fail at `compose up`; a second host port would not.
  Publishing worker for “debug” is a realistic demo edit.
- Suggested fix: After extracting publishes, fail if any entry on any
  service is missing a `127.0.0.1:` host IP (including long-form
  `host_ip`, `/tcp`, and list form). Assert `worker` (and any new
  service) has `ports` empty or loopback-only. Prefer a real YAML load
  if a parser is already available; otherwise scan every `ports:` value,
  not three allowlisted strings. Add a unit case that the dual-publish
  and worker mutations above fail.

### 2. VALID — Minor — Regex is format-coupled and the `endswith` fallback is wrong

- File: `backend/tests/test_compose_loopback.py` (`_service_port_entries`,
  lines 21–46 and 55–57)
- What's wrong: Body capture is `(?:    .*\n)+`, so a blank line before
  `ports:` drops the rest of the service (`got []`). Inline items use
  `[^\]]*`, so `"[::]:5432:5432"` becomes `['[::']`. Valid
  `127.0.0.1:5432:5432/tcp` and long-form `host_ip: 127.0.0.1` fail the
  test even though they are loopback. The fallback
  `entry.startswith("127.0.0.1:") and entry.endswith(mapping)` treats
  `127.0.0.1:15432:5432` as satisfying mapping `5432:5432` (I confirmed
  **PASS**).
- Why it matters: Today’s file is short-form inline with no blank lines,
  so the live test is green. A later reformat to long-form (the Compose
  way to set `host_ip`) would red the suite while still being correct,
  and a host-port typo would stay green. This is not a current exposure.
- Suggested fix: Parse mappings as `host_ip`, `published`, `target`
  (short or long form) and compare fields. Drop `endswith`. Fail closed
  on unparsed entries.
