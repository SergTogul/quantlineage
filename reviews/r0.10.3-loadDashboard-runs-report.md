# R0.10.3 loadDashboard RiskRun fallback

## Task
Make `loadDashboard()` fall back to `run_type: "dashboard"` RiskRun when HEAVY inline is refused

## Owner
Frontend / Risk UX Engineer

## Summary
When `POST /api/v1/risk/dashboard` returns HTTP 400 with `details.use === "/risk/runs"`, `loadDashboard()` now loads the demo book via `GET /portfolio`, enqueues `createRiskRun(..., { run_type: 'dashboard' })`, polls with `RISK_RUN_POLL_MS` / `isRiskRunTerminal` until COMPLETED or FAILED, and returns the `dashboard` result payload (same 10 App.jsx keys). Gate-off / 200 remains a single dashboard POST with no risk fan-out. Non-refuse 400/500 still throw without fallback. `json()` still surfaces `${status} ${statusText}` but parses the error body internally for refuse detection.
