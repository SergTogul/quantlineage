## Findings

### 1. VALID — Minor — Contract tests do not actually parse `needs:`

- Files: `backend/tests/test_pr_full_ci.py` (`_needs_ids`,
  `test_pr_full_job_name_is_explicit`)
- What's wrong: `_needs_ids` is not a YAML `needs:` reader.
  1. The inline matcher `needs:\s*\[([^\]]+)\]` is unanchored, so a
     comment `# needs: [backend, backend-quantlib, frontend, lint, e2e, postgres-smoke]`
     wins even when the real `needs:` list is missing or incomplete.
  2. The listed matcher uses `(?s)` / greedy `.+`, so the capture runs
     through the rest of the job. `findall(^      - (\S+))` then picks up
     step lines. On the **current** file the parsed set already includes
     the phantom id `name:` from `- name: Production-relevant jobs succeeded`.
- Why it matters: Acc 5’s exact mutations (delete job, delete a
  `      - <id>` line) fail. These hunts stay **green**:
  - comment-only inline `needs: […]` (no live `needs:` key)
  - comment with the full inline list, then drop `backend-quantlib` from
    the real list
  - drop `postgres-smoke` from `needs:` and add a later `      - postgres-smoke`
    step line
  - `if: false` / `if: always()` / schedule-only `if:` on `pr-full`
  - `continue-on-error: true` on `e2e`
  - `name: aggregator` plus `# name: PR-FULL`
  - job-level `name:` removed; step named `PR-FULL`
- Suggested fix: Parse the job with a YAML loader (or require
  `name: PR-FULL` as a 4-space key and `needs:` as a 4-space key whose
  sequence values are exactly the six ids). Reject `if:` and
  `continue-on-error` on `pr-full` and on each needed job. Assert the
  aggregator step is not `pytest`.
