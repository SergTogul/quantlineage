## Summary
When a native scenario kernel is selected (`hasattr(..., "pnl_from_arrays")`), `_pnl_via_scenario_kernel` now builds C-contiguous `float64` buffers — exposures `(1, 5)` and shocks `(n, 4)` — and calls `NativeScenarioKernel.pnl_from_arrays`. It no longer packs `Exposure` / `Shock` objects for that path.

The Python reference kernel still uses object `pnl()`. The default LINEAR / NumPy path (`get_scenario_kernel` → `None`) is unchanged. Methodology, unit conversion (vol × 100), and `KERNEL_PNL_*` / `KERNEL_ABI_*` tolerances are unchanged. VaR and QuantLib were not moved into C++.

Factor arrays must be 1-D and the same length; mismatch or a column vector fails closed (`ValueError`) before any kernel call. A defensive post-pack shape check raises `NativeKernelError(KERNEL_ERR_LENGTH)` if the packed buffers are not `(1, 5)` / `(n, 4)`.

TDD: three new tests failed first (`pnl` spy hit instead of `arrays`; `IndexError` / `TypeError` on bad shapes). After the wiring they pass, and the existing native ↔ NumPy / VaR-ES golden suite stays green.
