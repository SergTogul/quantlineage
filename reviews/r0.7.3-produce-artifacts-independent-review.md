## Findings

### 1. VALID — Minor — produce tests pin omitted VaR / ES / limits but not empty stress

- Files: `backend/tests/test_portfolio_hierarchy_artifacts.py` L128–138;
  `backend/app/services/portfolio_service.py` L283–303;
  `reviews/r0.7.3-produce-artifacts-report.md`
- What's wrong: `test_hierarchy_artifact_path_does_not_invent_var_es`
  asserts root VaR / ES zeros and `limits == []`. It does not assert
  `root.stress == []` (or that every node is empty). The producer leaves
  `stress_pnl` empty on purpose; the engine sum of empty maps is `[]`.
  That is honest leftover, but an invented “real” stress list
  (`DEFAULT_SCENARIOS` with `pnl=0`, or filled `stress_pnl`) would not
  fail this file.
- Why it matters: Empty stress is the other omitted-risk channel next to
  VaR zeros. The hunt is specifically whether empty stress is presented
  as a computed run. Today it is not (probe: `[]`). The produce suite
  does not lock that down.
- Suggested fix: Keep RF-008 open. Add
  `assert root.stress == []` (and optionally walk children). When a later
  producer fills `stress_pnl` from one book-level `StressEngine.run` on
  the existing snapshot, replace the empty assert with a sum-of-trade
  P&L reconcile — do not attach default scenarios as a fake run. Do not
  close RF-008 when doing so.
