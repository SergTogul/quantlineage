## Summary
`HierarchyEngine.build` and `risk_at` now accept an optional `artifacts` map keyed
by trade id. When a **complete** set is supplied for the node's positions,
additive fields (`market_value`/`pv`, `delta`, `gamma`, `vega`, `dv01`,
`fx_delta`, stress P&L by scenario) are summed from artifacts via
`TradeCalculationArtifact.add`. Pricing, risk.calculate, stress reprice, and
limit evaluation are not invoked on that path.

Incomplete maps fail closed (`ValueError` matching `incomplete`): missing trade
ids, or map key ≠ `artifact.trade_id`. No silent mix of reprice + artifacts.

When `artifacts` is omitted, existing behavior is unchanged: each node still
full-reprices (`_metrics` / `_stress` / `_limits` / VaR). **The default
no-artifact path still reprices.** RF-008 is **not** closed.

VaR / ES / limits on the artifact path are **omitted** (`var_95` / `var_99` /
`expected_shortfall_99` = 0; `limits` = `[]`). They are not invented from
historical vectors. Node VaR/ES from vectors remains later work.

TDD: new tests failed first (`unexpected keyword argument 'artifacts'`). After
the consume path, the required suite passed.

## Numerical conventions
- Units: currency PV; cash delta / cash FX delta; dollar gamma; vega = P&L per
  1 vol point; DV01 = P&L per +1bp; stress P&L in currency units. Same as
  `Valuation` / `TradeCalculationArtifact` / `HierarchyNode`.
- Sign convention: same as artifacts (no sign flip).
- Day count/calendar if relevant: n/a.
- Tolerances/reference: parent additive metrics equal `a.add(b)` within abs
  1e-9. Scenario keys are the union of the compute's positions; a trade
  missing a parent scenario contributes 0.0 (same merge as artifact `add`).
