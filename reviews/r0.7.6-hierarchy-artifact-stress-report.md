## Summary

Default trade-artifact producer now attaches per-trade stress P&L for the
same default scenario set used by portfolio stress (`DEFAULT_SCENARIOS` /
`HierarchyEngine.stress_scenarios`). Each scenario is applied **once** to
the market, then every trade is priced on that shocked snapshot
(scenario-once, price-many). Hierarchy aggregation already summed
`stress_pnl`; nodes now expose non-empty aggregated stress. Limits remain
`[]` on the artifact path (not faked).

## Changes

1. **`HierarchyEngine._trade_artifacts`**
   - Base: one `pricing.value` per position on the root market.
   - Historical: unchanged (`historical_pnl_for_valuation`).
   - Stress: for each scenario in `self.stress_scenarios`,
     `apply_scenario(market, scenario)` once, then
     `pricing.value(position, shocked)` per position; store
     `shocked_mv - base_mv` under scenario **id** (fallback name).
2. **`PortfolioService.hierarchy`**
   - Delegates to `HierarchyEngine.build` without a parallel producer, so
     service and engine default paths share one implementation.
3. **Limits**
   - Evaluated: attaching full `DEFAULT_LIMITS` via `LimitEngine.evaluate`
     would re-call `pricing.value` for concentration at every node and may
     run key-rate sensitivities — not cheap/correct without LimitEngine
     changes. Left `limits=[]`; documented as residual.
4. **Label difference (intentional)**
   - Artifact-path `StressResult.scenario` = scenario **id**.
   - `StressEngine.run` labels with scenario **name**.
   - P&L matches for the same scenario set (tests map id→name).
