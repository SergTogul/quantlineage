## Findings

### 1. VALID — Important — Two-worker GHA step can skip-green

- Files: `backend/tests/test_postgres_two_worker.py` L27–53; `.github/workflows/nightly.yml` L134–138; `backend/tests/conftest.py` L11–32
- What's wrong: `_live_postgres_url()` + module `pytestmark.skipif` is the only gate. It is evaluated at collection. Unset DSN, non-`postgresql` DSN, or any connect exception → skip. Nightly invokes `pytest -q --tb=short tests/test_postgres_two_worker.py` with no fail-on-skip. `conftest.py` only fail-closes QuantLib skips when `QUANTLINEAGE_REQUIRE_QUANTLIB` is set. Reproduced with the GHA DSN and no listener: **2 skipped, exit 0**.
- Why it matters: RF-016’s original hole was “CI is green when the expensive path skipped.” `continue-on-error` is absent (good). Skip is still green. `postgres:16-alpine` + health + `smoke_postgres.sh` on the same DSN make an accidental skip unlikely **if those steps remain**. Removing the service, or a probe failure after smoke, still greens the job.
- Suggested fix: When `CI` or `QUANTLINEAGE_NIGHTLY` is set, do not skip — fail if the DSN is missing or unreachable. Or fail the pytest step if `skipped == collected`. Keep local-optional skip when those env vars are unset.

### 2. VALID — Important — Native gate is liveness, not the milestone SLA

- Files: `.github/workflows/nightly.yml` L35–47, L69–83; `benchmarks/check_m6_sla.py`; `reviews/REMEDIATION_MILESTONE.md` § R0.12.4; `reviews/FINDINGS.md` RF-016 NIGHTLY; `reviews/qa-review.md` NIGHTLY
- What's wrong: The C++ step asserts JSON shape, `n_exposures==10000`, `n_shocks==1000`, `wall_ms >= 0`, `throughput_ops_per_s > 0`, then prints `native benchmark SLA-sized workload completed`. Any successful 10k×1k run has throughput > 0. The scenario harness is `--workload 1k_x_1k` and only asserts `cpp_header` / `python` keys. `check_m6_sla.py` (the existing SLA-K1/K2 checker on `10k_x_1k`) is never invoked. `runs-on: ubuntu-latest` on all three jobs; there is no labeled / self-hosted runner. `workflow_dispatch` is a manual trigger, not a runner label.
- Why it matters: Milestone R0.12.4 and RF-016 NIGHTLY ask for “native benchmark SLA” / “benchmark/SLA on labeled runner.” qa-review names `check_m6_sla.py` on a labeled runner. A green nightly native job does not mean SLA-K1/K2 held. Host-specific floors on `ubuntu-latest` can flake — that is a reason not to copy laptop floors, not a reason to call `> 0` an SLA.
- Suggested fix: Either run `check_m6_sla.py` on a stable labeled runner (record / fail-closed), or drop “SLA” from the step text and treat this job as compile+workload proof until a labeled runner exists. If only proof is intended, assert checksum / impl identity, not a fake throughput floor.

### 3. VALID — Minor — Nightly contract is comment-blind and substring-wide

- Files: `backend/tests/test_nightly_ci.py` L30–47, L54–84; `backend/tests/test_pr_full_ci.py` L39–65
- What's wrong: Same helpers as R0.12.2 Minor (`_needs_ids` unanchored inline `needs: […]`, `_on_block` raw text). Specified mutations fail `test_nightly_ci.py`. These hunts stay **green**:
  - comment-first `# needs: [backend, …]` plus inline `needs: […, nightly-native-benchmark]` (`_needs_ids` returns the comment; listed-line regex does not see inline)
  - PR-FULL `needs:` gains `native-benchmark` / `postgres-two-worker` / `full-reval-sample` (no `nightly` substring)
  - `test_pr_full_ci.py` after any extra need id (subset only)
  - `if: false` / `continue-on-error: true` on `native-benchmark` or `full-reval-sample` (postgres block is the only `continue-on-error` lock)
  - replace the `g++` compile with `echo g++ backend/native/src/benchmark.cpp --exposures` (required substrings remain)
- Why it matters: Acc 4’s exact strings are locked. A later comment-only or job-id leak, or an echo that keeps tokens, does not fail the suite. GHA itself would error if `ci.yml` `needs:` a job that does not exist in that workflow; merging nightly job keys into `ci.yml` would not.
- Suggested fix: Parse `on:` / `needs:` with a YAML loader. Forbid `pull_request` / `push` on nightly. Forbid nightly job ids **and** the three nightly keys in PR-FULL `needs:`. Reject `if:` / `continue-on-error` on each nightly job. Require a real `g++` compile line listing `benchmark.cpp`.
