## Findings

### 1. VALID — Minor — Default / demo snapshots still price at constructor wall-clock

- Files: `backend/app/domain/models.py:510`, `backend/app/pricing/quantlib.py:121`,
  `backend/app/sample.py:347-411`, `backend/app/market/demo_snapshot.py:202`,
  `backend/app/services/portfolio_service.py:293-296`
- What's wrong: Default `as_of="current"`. Demo markets and `DemoSampleMarksSnapshotAdapter` omit `as_of`. `calendar_as_of("current")` is `None`, so `value()` uses `QuantLibPricingEngine.evaluation_date`, which is `date.today()` when the factory constructs the engine. The previous-attribution copy now uses label `t0` (id remains `illustrative_previous`); both sides still resolve to the same engine date. Probe: default engine + `as_of="current"` → Settings `September 3rd, 2026` (today) while `snapshot.as_of` stayed `"current"`.
- Why it matters: This is the leftover wall-clock path. It is **not** attack 2 (the label is not rewritten on the snapshot). It **is** why RF-002’s wording `as_of: date` is not literally true. Backdated ISO/`date` snapshots do not take this path.
- Suggested fix: None required to APPROVE this slice. Production backdated runs must supply ISO or `date`. If a later slice wants zero wall-clock on the demo path, pin demo snapshots to an explicit calendar date (not `date.today()`).

### 2. VALID — Minor — `calendar_as_of` is fail-open when validation is bypassed

- Files: `backend/app/domain/models.py:170-186`,
  `backend/app/pricing/quantlib.py:60-62`,
  `backend/app/pricing/cache.py:140-147`
- What's wrong: `model_construct(as_of="later")` stores `"later"`. `calendar_as_of` returns `None` (same for `datetime`, datetime-ISO, invalid calendar strings). QuantLib and the valuation cache then use the engine date. `app/` has no `model_construct` caller; only tests use it. The report already names this.
- Why it matters: Fail-closed is the validated constructor / `model_copy` / `model_validate` path, not every Python object that looks like a snapshot. A future bypass that skips Pydantic would revive “unparseable label → wall-clock Settings.”
- Suggested fix: Accept as a documented bypass. Do not call `calendar_as_of` a second fail-closed gate.

### 3. VALID — Minor — Scenario memo identity still omits typed `as_of`

- File: `backend/app/risk/scenario_memo.py:45-56`
- What's wrong: Key is `base.id|content_hash|shocks|tag`. `content_hash()` excludes `as_of` (marks-only, by design). Probe: same `id="same"`, same spots/rates, `as_of` 2018 vs 2024 → **identical** memo keys. Valuation `market_cache_key` does **not** collide on that pair.
- Why it matters: Two in-memory bases that reuse an id (default id is `"current"`) and differ only by calendar date can replay a shocked snapshot whose preserved `as_of` is the first insert. Persistence primary key makes this unlikely for saved rows. Not the R0.3 factory-cache bug.
- Suggested fix: Optional later pin: include `as_of_wire(base.as_of)` (or `calendar_as_of`) in `scenario_memo_key`. Do not block this slice on it.

## Strengths

- Domain type is a real bounded union with a fail-closed validator, not a comment. `datetime` is rejected before the `date` subclass check.
- ISO regex + `date.fromisoformat` rejects unpadded dates, datetime-ISO, and impossible calendar days.
- `model_copy` re-runs `_AS_OF_ADAPTER.validate_python`, so bump/apply/scenario copies cannot leave a raw ISO string or `"illustrative_previous"`.
- Wire stays a string (`as_of_wire` / field serializer). Persistence column type is unchanged (`String(64)`).
- QuantLib and the valuation cache share `calendar_as_of`. Typed `date` and ISO strings both drive Settings; I reproduced the R0.3 factory leak numbers and the leak is gone.
- RF-002 was not closed in FINDINGS. Labels were kept on purpose so demo/fixture snapshots are not silently bound to `date.today()`.
