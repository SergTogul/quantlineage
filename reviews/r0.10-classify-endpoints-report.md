# R0.10.1 Classify endpoints

## Task
R0.10.1 Classify API endpoints as interactive vs heavy (RF-015)

## Owner
Backend / API Engineer

## Status
**DONE**

## Summary
Added a documented execution-class contract that marks each owned HTTP route INTERACTIVE or HEAVY. Cheap paths are completed-run GET, lightweight summary, and small factor/limit drilldown. Listed heavy examples (FULL_REVALUATION, large hierarchy, reverse multi, expensive what-if, large scenario eval, heavy contribution) exist in OpenAPI and are not interactive-only. No job platform, no numerical-method change, no extra auth, and no router behavior change — the map does not enqueue or reject requests.

## Public/interface changes
- New module `app.api.execution_class`:
  - `ExecutionClass.INTERACTIVE | HEAVY`
  - `ENDPOINT_EXECUTION_CLASS` — unversioned `(METHOD, path)` map; `/api/v1` dual-mounts share the class via `normalize_path`
  - `LISTED_HEAVY_ROUTES` — R0.10.1 / RF-015 examples
  - `classify(method, path, *, methodology=None)` — `methodology=FULL_REVALUATION` upgrades methodology-bearing routes (including `POST /risk/summary`) to HEAVY
  - `is_interactive_only(method, path)` — False for every listed heavy route and for methodology-bearing routes
- HTTP handlers, OpenAPI, DTOs, and auth are unchanged.

### Interactive (cheap)
| Method | Path | Reason |
|---|---|---|
| GET | `/risk/runs/{run_id}` | completed-run retrieval |
| POST | `/risk/summary` | lightweight summary (default LINEAR / DELTA_GAMMA; FULL_REVALUATION is HEAVY) |
| POST | `/risk/factors` | small factor drilldown |
| POST | `/risk/limits/drilldown` | small scoped drilldown |
| GET | `/health`, `/portfolio`, `/portfolios`, `/portfolios/{portfolio_id}` | catalog / health |
| GET | `/risk/stress/scenarios`, `/risk/stress/scenarios/formal` | scenario definitions |
| POST | `/market/snapshot` | snapshot construction, no risk compute |

### Listed heavy (must not be interactive-only)
| Method | Path | Milestone example |
|---|---|---|
| POST | `/risk/var` | FULL_REVALUATION |
| POST | `/risk/es` | FULL_REVALUATION + contribution |
| POST | `/risk/var/compare` | FULL_REVALUATION |
| POST | `/risk/hierarchy` | large hierarchy |
| POST | `/risk/stress/reverse/multi` | reverse multi-factor |
| POST | `/risk/what-if` | expensive what-if |
| POST | `/risk/stress/evaluate` | large scenario evaluation |
| POST | `/risk/stress/evaluate/custom` | large scenario evaluation |
| POST | `/risk/stress/formal/evaluate/custom` | large scenario evaluation |
| POST | `/risk/contributors` | heavy contribution analysis |
| POST | `/risk/change-attribution` | heavy contribution analysis |

Other synchronous compute POSTs (`/stress`, custom/formal stress, reverse single, compare, attribution, limits, query, `POST /risk/runs` enqueue) are also HEAVY in the map so they cannot be treated as interactive-only.

## Known limitations / risks
- Classification does not move work off the request thread. Dashboard `loadDashboard()` still fans out nine synchronous POSTs (RF-015 / R0.10.2).
- Default `POST /risk/summary` stays INTERACTIVE; `methodology=FULL_REVALUATION` is HEAVY and `is_interactive_only` is False for that route.
- `POST /risk/limits/drilldown` is marked INTERACTIVE as the small-drilldown slot; a large unscoped book can still be expensive. R0.10.3 backpressure is the workload bound.
- `POST /risk/runs` is HEAVY (enqueue of heavy work), not a compute handler. GET of a completed run is INTERACTIVE.
