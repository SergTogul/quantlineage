## Status
**DONE** (slice only — RF-009 not closed)

## Summary
FastAPI deps and `python -m app.worker` now construct pricing + historical risk through one callable, `build_portfolio_service()`. The worker no longer builds `HistoricalRiskEngine()` (default synthetic) while the API used `create_historical_dataset()` (default demo CSV). `RiskRunWorker.submit` writes first-class spec columns from the request blob and/or the factory-resolved dataset: demo CSV → `demo-historical-factors` / `v1`; synthetic → `synthetic-historical-factors` / `v1`; `as_of` when parseable as `date | current | t0`; `calculation_config` from request or engine seed/observations. `RiskRunService.enqueue` accepts those fields as optional kwargs so old call sites stay valid. `RiskRunCreateRequest.request` remains the transport. No VaR numbers, demo CSV, or QuantLib changes. RF-009 stays open for R0.8.3 persistence identity and R0.8.4 typed request schemas.

## Known limitations / risks
- RF-009 remains **open**. This slice unifies construction and records dataset identity on enqueue; it does not make persistence identity server-owned or replace the untyped `request` dict.
- Spec `historical_dataset_id` on the row is a label of the factory-resolved (or request-supplied) dataset. The worker still executes whatever engine it was constructed with; a request that names a different dataset than the process factory does not switch engines (R0.8.4 typed requests / later binding).
- `calculation_config` remains the closed R0.8.1 knob set (`observations`, `seed`, `confidence`).
- Unparseable `as_of` in the request blob is dropped rather than rejected, because `request` is still an untyped envelope.
- Interactive HTTP risk routes already used the API factory; only the Compose worker path was on the synthetic default. Aligning them can change worker VaR vs the previous worker default if anyone compared those two paths — that was the RF-009 bug, not a methodology change.
