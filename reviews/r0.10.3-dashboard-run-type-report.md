## Summary
`POST /risk/runs` (and `/api/v1/risk/runs`) now accepts `run_type: "dashboard"`. The worker calls `PortfolioService.dashboard(...)` and stores a COMPLETED result whose payload has the same top-level keys as `DashboardBatchResponse`: `portfolio`, `summary`, `stress`, `threats`, `contributors`, `limits`, `factors`, `varReport`, `hierarchy`, `attribution`.

Critical: `_serialize_result` wraps lists as `{"items": [...]}` for other run types. Dashboard uses a dedicated `_serialize_dashboard_result` so lists stay JSON arrays and BaseModels dump to objects — matching App.jsx / the sync batch route. Existing run types are unchanged.
