# R0.11.5 Shared deployment auth gate

## Task
R0.11.5 Shared deployment auth gate (RF-014 / SEC-001 remaining)

## Owner
Backend / API Engineer

## Summary
Local demo (loopback bind, default Compose) stays unauthenticated. A shared / non-loopback profile — `QUANTLINEAGE_SHARED_DEPLOYMENT=1` or `QUANTLINEAGE_BIND` outside `{127.0.0.1, localhost, ::1}` — fails closed without `QUANTLINEAGE_API_TOKEN` (refuses to boot) and rejects unauthenticated API / dual-mount requests with 401. `Authorization: Bearer <token>` is accepted. `/health`, `/docs`, `/redoc`, and `/openapi.json` stay open. This is a single shared-secret gate, not OIDC, object ACLs, TLS, or production IAM. Documented as local vs shared vs not-production-like in `BUILD_NOTES.md`.

TDD: `tests/test_shared_auth.py` was written first and failed (module missing). Implementation then turned those tests green.

## Known limitations / risks
- Single shared token for the whole API. No per-user identity, no object ACLs / IDOR protection, no TLS termination, no secret manager.
- In-container `uvicorn --host 0.0.0.0` (Dockerfile) is not treated as a host publish. Operators who publish Compose ports beyond loopback must set `QUANTLINEAGE_SHARED_DEPLOYMENT=1` (or `QUANTLINEAGE_BIND=0.0.0.0`) and `QUANTLINEAGE_API_TOKEN`.
- Demo Postgres credentials are unchanged. Frontend local demo does not send a Bearer token (correct for the unauthenticated local profile).
- CORS preflight `OPTIONS` is allowed without a token so a future shared UI can still handshake.
- This slice does not close RF-014 object-authorization / TLS / secret-management residuals; those remain “not production-like.”
