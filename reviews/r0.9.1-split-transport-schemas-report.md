# R0.9.1 — Split HTTP transport schemas out of domain

## Task
RF-010 / R0.9.1 — move HTTP request/response DTOs from `app.domain.models` to `app.api.schemas`

## Owner
Backend / API Engineer

## Summary
Obvious HTTP bodies (`CustomStressRequest`, `RiskQueryRequest` / `RiskQueryResponse`,
`LimitDrilldownRequest`, `RiskRunRequestBody` and per-`run_type` aliases,
`RiskRunCreateRequest`, `RiskRunView`) now live in `backend/app/api/schemas/transport.py`
and are re-exported from `app.api.schemas`. Domain entities and risk *result* types stay
in `app.domain.models`. Domain does not import FastAPI or `app.api`. JSON field names,
`FiniteFloat`, and existing `extra='forbid'` behavior are unchanged. No DI container;
one grouped transport module (not one-file-per-class).

**Disposition: IN PROGRESS** — do not CLOSE RF-010. R0.9.2 typed risk results and
R0.9.3 lifespan composition remain. Dual-use engine/service inputs
(`AttributionRequest`, `RiskChangeAttributionRequest`, `WhatIfRequest`) stay in domain.

TDD: `test_domain_models_does_not_define_http_transport_bodies` failed first (names
still in `domain.models`); schemas import failed until the move.
