## Summary
R0.12.5 already fail-closed the C ABI (version / length / null). This slice adds the two remaining RF-017 items only:

1. `NativeScenarioKernel.pnl_from_arrays` passes C-contiguous `float64` NumPy buffers into `quantlineage_portfolio_scenarios` without a pack copy. Fortran / strided / non-float64 inputs are made contiguous first. The object `pnl()` API is unchanged (still packs `Exposure`/`Shock` lists).
2. The C++ kernel stays serial when `n_exposures * n_shocks < KERNEL_PARALLEL_MIN_WORK` (4096), or when `workers <= 1` / `n_shocks <= 1` / empty book. Tiny workloads (including the product 1×S Historical VaR shape) do not spawn threads per call. Above the threshold the existing stdlib shock-partition pool is unchanged (no second strategy, no persistent process pool).

P&L math, ABI version, and length/null fail-closed predicates are unchanged. VaR and QuantLib were not moved into C++. `historical.py` was not edited (still uses the object `pnl()` path).

TDD: new `pnl_from_arrays` tests failed first (`AttributeError`). C++ tiny-work predicates / `kernel_last_used_workers_flag` were added against the new serial gate. Parallel equivalence tests were resized to 4×2048 so they still exercise workers above the threshold.

## Known limitations / risks
- `historical._pnl_via_scenario_kernel` still builds Python `Shock` lists and calls `pnl()`. Wiring `pnl_from_arrays` there is a Portfolio Risk handoff (this change did not edit `historical.py`).
- Large E×S still creates stdlib threads per call. RF-017 allowed “reuse a pool **or** serial below a threshold”; this slice uses the threshold so tiny/1×S work never pays spawn, without a process-lifetime pool (fork/shutdown surface).
- `kernel_last_used_workers_flag` is a process-global test hook, not part of the C ABI.
- Existing on-disk `libriskkernel` does not need a rebuild for the NumPy path (same C ABI). The serial threshold is header-only; rebuild the `.so` / `kernel_test` to pick it up.
- Do not close RF-017 in `FINDINGS.md` from this report alone — Lead/QA own that file.
