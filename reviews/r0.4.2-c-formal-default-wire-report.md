# R0.4.2-C — Formal Scenario as default HTTP list wire

Status: **COMPLETE pending review** (2026-09-09)  
Owner: Stress & Scenario Engineer (API surface coordinated with Backend)  
Related: RF-004 (stays IN PROGRESS), RF-011 (stays IN PROGRESS), milestone § R0.4.2

## Goal

Make formal `ScenarioWire` the default client list path and retire the dual
list semantics (`/scenarios` vs `/scenarios/formal`).

## What changed

- **Breaking:** `GET /api/v1/risk/stress/scenarios` (and legacy mount
  `/risk/stress/scenarios`) returns `list[ScenarioWire]` (`category`,
  `shocks[]`, …) instead of legacy `StressScenario` dicts
  (`equity_shock`, `rates_shift_bps`, …).
- `GET .../scenarios/formal` kept as an **identical JSON alias** so clients
  already on `/formal` keep working (OpenAPI description documents parity).
- Shared `_formal_scenario_wires` helper projects DI `StressScenario`
  definitions via `stress_to_wire` (needs default market snapshot for
  scalar expansion).
- No `/scenarios/legacy` path: frontend and tests do not consume the
  StressScenario list shape; prefer formal.

## Explicitly unchanged

- Domain `StressScenario` / engine `ScenarioLike` support (out of scope).
- Legacy StressScenario **POST** bodies on `/stress/custom`,
  `/evaluate/custom`, `/compare` (frontend `scenarioPayload` still uses
  them).
- Formal POST twins under `/risk/stress/formal/custom` and
  `.../formal/evaluate/custom`.
- RF-004 / RF-011 not closed.

## Breaking change note

Clients that parsed `GET /risk/stress/scenarios` as StressScenario scalars
must switch to formal wire (`shocks` array with `factor_type` / `amount` in
MarketSnapshot.bump units). Use `/scenarios/formal` if already migrated; it
now matches the default exactly.

## Residual (RF-004 / RF-011)

| Residual | Why open |
|---|---|
| Dual StressScenario POST bodies | UI `scenarioPayload` → `/evaluate/custom`; compare/custom still accept StressScenario |
| Typed nesting (RF-011) | Flat dict market storage + broader curve/surface typing still open |
| Unit acceptance goldens | Already covered by R0.1.3 / R0.4.3 / R0.4.2-A; this slice is wire converge only |

Do **not** close RF-004 or RF-011 from this slice.

## Frontend

No consumer of `GET /risk/stress/scenarios` in the React app (dashboard /
threat cards use POST results). No frontend file changes in this slice.
`scenarioPayload` remains legacy StressScenario for custom evaluate POST —
documented residual above.
