## Why CLOSE (not KEEP OPEN)

Version is stored, returned, compare-and-swap checked, and stamped on the run header. A comment-only or unchecked column would have kept the finding open.

Would this gate defend CLOSE to a second reviewer? **Yes**, provided the named residuals stay written (seed `save`, live calculate POST, RF-014 ACLs, client id on first create).

## Residuals (accepted; not blocking close)

1. **Legacy `save` upsert** remains for seed callers. Insert starts at 1; overwrite bumps without CAS. Submit does not call `save`.
2. **Live calculate still POSTs a full book** (explicit debug/demo path).
3. **Object ACLs / IAM** — RF-014.
4. **Client-chosen id on first create-if-absent.**
5. Execute/reproduce uses the **current** stored book. The run header records the version that was current at submit; this is not a per-revision book archive.
