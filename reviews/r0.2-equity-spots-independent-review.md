## Findings

### 1. VALID — Minor — Required-spot helper is duplicated

- Files: `backend/app/pricing/builtin.py`, `backend/app/pricing/quantlib.py`
- What's wrong: Identical `_required_equity_spot` functions live in both
  modules. A later family slice can tighten one (trade id, shared lookup,
  dividend/vol) and leave the other on the old contract.
- Why it matters: The overlay and Builtin must stay aligned; this slice
  already depends on that. Not a current behavior bug — both raise the
  same `factor_key` today.
- Suggested fix: One shared helper next to `MissingMarketDataError`,
  imported by both pricers.

### 2. VALID — Minor — `MissingMarketDataError` still names only the factor key

- File: `backend/app/market/demo_snapshot.py` (unchanged this slice)
- What's wrong: Brief §3 asked the typed error to name trade id **and**
  factor key. Call sites still pass only `equity_spots[<symbol>]`.
- Why it matters: Same shape as approved R0.2-A cash equity. Logs for a
  multi-name book will not say which trade failed. Not a silent fallback.
- Suggested fix: Thread `position.id` into the error when the next
  equity-family slice touches the helper.

### 3. VALID — Minor — Risk-path coverage for futures/options is Builtin-only in tests

- File: `backend/tests/test_market_authority.py`
- What's wrong: Cash equity has
  `test_linear_var_raises_when_supplied_snapshot_omits_equity_spot`.
  Futures/options add Builtin + QuantLib `value()` cases and “beats
  trade-local” cases, but not LINEAR / FULL / cache. QuantLib tests call
  `import_quantlib()`, which skips unless QuantLib is installed or
  `QUANTLINEAGE_REQUIRE_QUANTLIB=1`.
- Why it matters: I probed Cached + Historical LINEAR on the AUTH future
  against an empty snapshot; both raised. Existing
  `test_quantlib_pricing.py` /
  `test_quantlib_golden.py` `market=None` goldens still pass. This is a
  missing safety net, not an open production hole.
- Suggested fix: Parametrize the existing LINEAR missing-spot case over
  `_future_book` / `_option_book`, or keep relying on `value()` plus the
  CI QuantLib hard gate.

## Items checked and not findings

- Builtin future/option and QuantLib overlay no longer call
  `equity_spots.get(symbol, position.spot)` when `market is not None`.
  Cash equity was only refactored onto the same helper; behavior matches
  committed R0.2-A.
- QuantLib copies onto a local `model_copy`; the caller position is not
  mutated. Overlay raises before the session if the key is absent.
- `market.equity_spots` is a `mappingproxy`; `[]` still raises `KeyError`
  and is translated.
- `LegacyDemoPricingAdapter` / demo adapter already seed
  `equity_spots` from future/option `spot`, so the named no-market path
  still works after this fail-closed change.
- `trade_cache_key` already drops future/option `spot` (R0.2-A). This
  slice did not need a new cache test to be correct.
- Existing option/future tests that pass a snapshot already include the
  symbol (`test_surface_vol_pricing.py`, `test_quantlib_pricing.py`,
  `test_var_methodology.py`, `test_full_reval_golden.py`). Goldens that
  call `value(position)` with no market are unchanged.
- `attribution.py` still does
  `equity_spots.get(sym, position.spot|price)`. Out of this file list
  and not claimed.
- FX / bond / swap / IR `.get` fallbacks were not removed.
