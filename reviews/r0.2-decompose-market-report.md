## Summary
`ScenarioAttributionEngine.decompose` no longer infers a `MarketSnapshot` from
the book when `market` is omitted or `None`. It raises
`ValueError("production risk calculation requires an explicit MarketSnapshot")`
via `require_explicit_market` (same type and wording as VaR / hierarchy /
stress) and does not call `demo_market_snapshot` or
`DemoAggregateMarketDataProvider.snapshot`.

The signature stays `market: MarketSnapshot | None = None` so the failure is a
domain `ValueError`, not a `TypeError`. Empty books still require an explicit
snapshot before the empty-contribution early return. `StressEngine.evaluate` /
`contributions` already required a snapshot and continue to pass it through.

`demo_market_snapshot` remains for named demo/sample helpers and tests that opt
in. `DemoAggregateMarketDataProvider` is still constructed as an unused
attribute so existing service adapter tests can assert it is not called.

TDD: new omit-`market=` tests failed first (`DID NOT RAISE ValueError`) while
`decompose` still inferred demo marks. After fail-closed, those tests passed
and direct `decompose` callers in `test_scenario_attribution.py` now pass
fixtures or `demo_market_snapshot` in tests only.
