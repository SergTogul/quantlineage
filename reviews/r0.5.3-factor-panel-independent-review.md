## Findings

### 1. VALID — Minor — `is_per_name_per_tenor_panel` is a constant `True`

- Files: `backend/app/risk/factor_panel.py` L167–169; `backend/tests/test_factor_panel.py` L87–92
- What's wrong: The property does not inspect factors, tenors, or `projection`
  (except that `__post_init__` rejects `"four_macro_demo"`). Probe: one equity
  column, and `projection="not_a_panel"`, both report `True`. The new test
  only asserts the flag on a well-formed four-factor panel.
- Why it matters: Callers cannot use the flag to distinguish a per-name /
  per-tenor panel from a one-factor or mislabeled construct. Independence
  still holds on the typed store (attack 1). This is a residual default, not
  a live four-macro identity.
- Suggested fix: Derive the flag from contents (at least two names and two
  tenors) or document it as a type-level constant and stop treating it as a
  content check. Optional. Not required to keep this leftover.

### 2. VALID — Minor — Duplicate dates construct; lookup returns the first row

- Files: `backend/app/risk/factor_panel.py` L142–165, L175–179
- What's wrong: `__post_init__` aligns `obs.as_of` with `dates[i]` but does
  not require unique dates. Probe: `from_pairs(dates=[D1, D1], rows=[[(AAA,
  0.01)], [(AAA, 0.99)]])` succeeds; `observation_on(D1)` and `change(D1,
  AAA)` return `0.01`.
- Why it matters: The stated contract is `date → RiskFactor → change`.
  Duplicate dates make the date key a first-match scan. Not wired; no
  production reader. Fail-closed already exists for empty / duplicate factor
  identity / length mismatch.
- Suggested fix: Reject duplicate dates in `__post_init__`. Optional for this
  leftover; required before wiring.

### 3. VALID — Minor — Non-finite changes are stored

- Files: `backend/app/risk/factor_panel.py` L88–93
- What's wrong: `_pairs_to_changes` does `float(amount)` with no finite
  check. Probe: `nan` and `inf` round-trip.
- Why it matters: A later VaR wire would poison P&L. The type is storage
  only today. Demo four-column arrays also do not reject non-finite at
  construct. Not a fake per-name contract.
- Suggested fix: Fail closed on non-finite amounts when this type is wired.
  Optional for this leftover.
