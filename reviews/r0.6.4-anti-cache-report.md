# R0.6.4 Anti-Cache Report

## Task

R0.6.4 — Remove anti-cache behavior on unique shocked markets.

## Owner

Quant Pricing Engineer.

## Summary

Unique-shock / FULL_REVALUATION execution no longer consults or populates the per-snapshot valuation LRU. `CachedPricingEngine` skips key hashing, LRU get/put, and cached `model_copy` while `bypass_valuation_lru` is active. Production full-reval loops (historical series/panel, VaR position P&L, ES factor-isolated full-reval) enter that context for shocked snapshots only. Base-snapshot valuations still use the LRU. `shocked_value` always bypasses because the shocked market is unique by construction. RF-007 remains `IN PROGRESS`.

## What Was Bypassed

- Per-snapshot NPV LRU keyed by trade economics + `MarketSnapshot.content_hash` + pricing config.
- Unique historical / panel shocked snapshots in `full_revaluation_pnl_series`, `full_revaluation_pnl_from_panel`, `VaRAnalytics._full_reval_position_pnls`, and ES factor-isolated full-reval.
- `CachedPricingEngine.shocked_value`.

## What Still Caches

- Repeated valuations of the same trade + same base snapshot + same config (dashboard / Greeks / second full-reval base PV).
- QuantLib adapter structure reuse from R0.6.3 (live `SimpleQuote` handles; not NPV).
- Curve-construction LRU (`QUANTLINEAGE_CURVE_CACHE`): equity/FX/vol bumps that leave rate marks unchanged can still hit. That is not a per-unique-snapshot NPV anti-cache.

## Numerical Conventions

- No pricing convention changed.
- Unique-shock full-reval P&L matches the inner/cold engine at absolute `1e-12`.
- Existing full-reval goldens (`[-100, 0, 50]` unit-equity identity) remain the reference.

## Tests

Added `backend/tests/test_pricing_anti_cache.py`:

- Bypass context does not consult/populate the LRU and does not build per-snapshot cache keys.
- Unique-shock `full_revaluation_pnl_series` and VaR full-reval spy LRU get + `valuation_cache_key`: only the base snapshot is keyed/stored.
- Cached full-reval P&L matches an uncached inner engine at abs `1e-12`.
- A later base valuation still hits after unique-shock bypass.
- `shocked_value` bypasses the LRU.

Existing `test_pricing_cache.py` hit/miss/config goldens remain valid for repeated base valuations.

## Known Limitations / Risks

- Reverse-stress and hierarchy/stress `value()` calls on unique shocked snapshots still use the LRU unless they go through `shocked_value` or `bypass_valuation_lru`. Those paths are outside this FULL_REVALUATION wiring.
- Zero-shock historical observations now reprice instead of hitting the base LRU entry. Numerical identity is unchanged; the hash/lookup tax is avoided for the whole unique-shock loop.
- Curve and scenario memos are unchanged.
- This is a structural anti-cache proof, not an end-to-end wall-time SLA.
