## Findings

### 1. VALID — Minor — `add(..., trade_id=)` and result `trade_id` are untested

- Files: `backend/tests/test_trade_artifacts.py` L130–189;
  `backend/app/risk/trade_artifacts.py` L180–205;
  `reviews/r0.7.2-trade-artifacts-report.md` (claims the kwarg is the
  R0.7.3 node-key hook)
- What's wrong: Every add test uses `a + b` and never reads
  `total.trade_id`. Nothing calls `add(..., trade_id=)`. A regression
  that dropped the override, concatenated ids, or stamped a constant
  would stay green.
- Why it matters: R0.7.3 is supposed to sum distinct trades into a
  stable node id via that kwarg. The method works today (probe:
  `a.add(b, trade_id="book:X").trade_id == "book:X"`; `a+b` keeps
  `"t1"`). This is a missing pin, not a live wrong default.
- Suggested fix: Assert ` (a + b).trade_id == a.trade_id ` and
  `a.add(b, trade_id="desk:X").trade_id == "desk:X"`. Optional for this
  leftover. Empty override should keep failing via `_require_trade_id`.
