## Summary
`PortfolioService.hierarchy` now attaches a historical P&L vector **once per
trade** from the already-valued Greeks via `approximate_pnl_series` (shared
`HistoricalRiskEngine` factor observations, LINEAR / DELTA_GAMMA). Lengths
match across the book. This is one series per trade, **not** a book-level
series split.

`HierarchyEngine._node_from_artifacts` sums those vectors (`TradeCalculationArtifact.add`)
and computes `var_95` / `var_99` / `expected_shortfall_99` from the **summed**
node vector. Convention matches `HistoricalRiskEngine.calculate` and
`test_var_es_golden.py`:

- loss = −P&L
- `numpy.quantile` default linear interpolation
- VaR and ES floored at zero
- ES is the mean of losses ≥ VaR

`var.py` inlines the same quantile in `VaRAnalytics.report`; there is no
extracted helper, so hierarchy replicates those four lines rather than
repricing through `report()`.

All-omitted vectors stay zeros. Mixed present/absent vectors fail closed
(existing `add()` rule). Direct `HierarchyEngine.build` without `artifacts=`
still full-reprices. **Do not close RF-008.**

TDD: new consume-path tests failed first (`var_95` / `var_99` were 0.0 vs
9.95 / 10.79 on controlled vectors). The producer “does not invent VaR”
zero-assert was replaced with an independent vector-sum assertion (expected
~20.61); it failed on zeros before the producer attached series. After the
consumer + producer, the required suite passed.
