### 1. VALID — Minor — Pytest would stay green on a later echo of the pinned JSON

- Files: `backend/tests/test_full_reval_bench.py` L25–52
- What's wrong: The runtime test pins the subprocess JSON hash. It does not independently recompute shocked PV − base PV or re-hash the engine vector. The companion test is token-grep (`full_revaluation_pnl_series` / `checksum` / `n_obs` / no `check_m6_sla` / no `throughput > 0` / pin string present). Specified honest mutations of the **on-disk script** fail (sentinel checksum raises; missing pin fails test 1). These hunts stay **green**:
  - replace the function body with `print(json.dumps({…checksum: EXPECTED_CHECKSUM…}))` while leaving the `full_revaluation_pnl_series` substring (import or comment)
  - `# check_m6_sla.py` / `# throughput > 0` comments (the regexes look for imports / `check_m6_sla.py ` / `throughput > 0`, not a live invoke)
- Why it matters: Acc 2’s pin is real today because the script computes. A later leftover-style echo that keeps tokens would not fail this suite. That is the same comment/token class as R0.12 hierarchy-bench Minor, not a live fake SLA.
- Suggested fix: In pytest, rebuild the 120-obs book, call `full_revaluation_pnl_series`, hash `{x:.12f}`, and assert that digest equals both the subprocess `checksum` and the pin. Keep the no-`throughput` / no-`check_m6_sla` locks.
