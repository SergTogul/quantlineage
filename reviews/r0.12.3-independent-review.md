## Findings

### 1. VALID — Important — Hedge rerun does not verify changed risk

- Files: `e2e/tests/r0-critical-journey.spec.ts` L107–125; `reviews/r0.12.3-report.md` “Known limitations”
- What's wrong: After Compare hedge, the spec only checks `.hedge-compare-result` is visible and contains `Hedge cost` / `99% VaR` / `99% ES` plus a table row. `HedgeCompare` renders `money(base_var_99 ?? 0) → money(hedged_var_99 ?? 0)`, so `$0 → $0` or identical before/after still matches `/99% VaR/`. Milestone R0.12.3 ends `→ verify changed risk`. QA-014’s recommended test is explicit: network-assert compare and `hedged_var_99 !== base_var_99` from API JSON when SPY equity is flattened. The report’s excuse (“would invent/compare client-side”) contradicts QA-014 (“still no client-side math”).
- Why it matters: The failure QA-014 said would escape — broken hedge, 200, a table — still escapes. This is the step that was supposed to make the journey defensible versus stitching existing panel smokes.
- Suggested fix: `waitForResponse` on `POST /api/v1/risk/stress/compare` with `ok()`. From JSON, assert `base_var_99 !== hedged_var_99` (and/or `var_improvement !== 0`, or a scenario `base_pnl !== hedged_pnl`). Do not pin dollar amounts. Optional: assert the two rendered money strings on the VaR line differ.

### 2. VALID — Minor — Response and non-compare paths are not locked

- Files: `e2e/tests/r0-critical-journey.spec.ts` L37–38, L81–98, L54–61, L107–111
- What's wrong: Custom and compare use `waitForRequest` only. Dashboard `99% VaR` / `99% ES` `$` text, Component VaR row count, and Load ES (labels + table) have no URL/status/body check. QA-014 listed `/risk/var` among the network assertions; it is never waited.
- Why it matters: Wrong path / no network fails the two POSTs. A stub that issues those POSTs and paints Loss/NAV/hedge chrome, or a client-faked ES/KPI strip, still passes.
- Suggested fix: Pair each intercepted POST with `waitForResponse` + `ok()`. Optionally wait for `POST /api/v1/risk/var` (or `/risk/es`) before treating KPI / contributor panels as API-backed.

## REJECTED

1. **Rejected — “visibility-only hedge is required by don’t-invent-numbers.”** Relational asserts on compare JSON do not invent VaR/ES. QA-014 already specified that invariant.
2. **Rejected — “dashboard smoke makes this spec redundant.”** Prefix overlap is the journey. Wire units + compare body + SPY qty are extra.
3. **Rejected — “hedge-compare is only UI labels.”** Request path and body are asserted. The hole is the missing change/response predicate (Findings 1–2), not a label-only hedge step.
4. **Not a finding — preset SPY-flat vs free-form “add hedge trade.”** No such editor exists. Using `HedgeCompare` matches the product. The defect is failing to assert the compare result changed risk.
