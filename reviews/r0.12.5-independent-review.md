## Findings

### 1. VALID — Critical — GHA native smoke still builds `kernel_test.cpp` alone

- Files: `.github/workflows/ci.yml` L65–80; `backend/native/tests/kernel_test.cpp` L2, L70–111; `backend/native/README.md` L39–45; `backend/tests/test_native_kernel.py` L74–88
- What's wrong: `kernel_test.cpp` now calls `quantlineage_kernel_abi_version` and `quantlineage_portfolio_scenarios` (defined only in `risk_kernel_capi.cpp`). Pytest and README were updated to compile both TUs. The production CI step was not:

  ```text
  g++ -std=c++20 -O2 -pthread -I native/include \
    native/tests/kernel_test.cpp -o /tmp/kernel_test
  ```

  Local reproduction of that file list: linker error, exit 1. Comment at L66 (“Flags match test_native_kernel.py / README”) is false. No workflow-contract test pins this compile line (`test_pr_*_ci.py` do not).
- Why it matters: `backend-pytest` “Native C++ compile and smoke” cannot produce a binary that contains the new ABI entry. The shared-lib compile is after the failing link. R0.12.2/R0.12.5 treat native compile as part of PR-FULL. A green GHA native smoke with this workflow is not available.
- Suggested fix: Compile `native/src/risk_kernel_capi.cpp` in that step with the same flags pytest/README now use. Lock the file list in a workflow contract test so a one-file compile fails the suite.

### 2. VALID — Important — Count×stride walk is not bounded by `n_*_doubles`; wrap guard untested

- Files: `backend/native/src/risk_kernel_capi.cpp` L31–55; `backend/native/include/risk_kernel.hpp` L86–100, L153–158; `backend/native/tests/kernel_test.cpp` L86–95; `backend/tests/test_native_kernel.py` L268–288
- What's wrong: After the predicates, the C ABI calls `portfolio_scenarios_flat_into(exposures, n_exposures, shocks, n_shocks, out, 0)`. That function never sees `n_exposure_doubles`, `n_shock_doubles`, or `n_out`. It reads `exposures[i*5 + 0..4]`, `shocks[j*4 + 0..3]`, writes `out[0..n_shocks)`.

  The `kMax / STRIDE` guard is the backstop for wrap-around equality. On 64-bit `size_t`, `n_exposures = SIZE_MAX/5 + 1` makes `*5` wrap to **4**, which would satisfy `n_exposure_doubles == exp_need` if the guard is deleted. `n_shocks = SIZE_MAX/4 + 1` wraps `*4` to **0**. No test passes those counts. Removing L32–35 stays green.

  Length cases that do exist (`n_exposure_doubles=4`, `n_shock_doubles=3`, `n_out=0`) keep a 5-double / 4-double / 1-double allocation. `kernel_test.cpp` never mismatches `n_shock_doubles` at all.
- Why it matters: “Mismatch → no overrun” is a claim about the predicate, not a demonstrated tight-buffer or wrap case. A skipped or wrap-bypassed check still walks `n_exposures*5` / `n_shocks` writes.
- Suggested fix: Add a ctypes/C case with wrap-sized `n_exposures` or `n_shocks` expecting `ERR_LENGTH` and an unchanged sentinel (no huge allocation). Add a tight `n_shocks=2` / `n_out=1` / 1-double `out` case (and a 5-double buffer with `n_exposures=2`) so a skipped predicate is an actual overrun under ASan, not only a wrong `rc`.
