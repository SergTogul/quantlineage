## Verdict: REVISE

`FiniteFloat` on the domain request models is real and I verified the six
acceptance checks against source and HTTP, not from the implementer report.
That is not enough to approve the slice. SEC-006 named
`FactorShockWire.amount` as a primary location. It is still an unconstrained
`float` on live formal-stress routes. This slice then applied `FiniteFloat`
to `StressScenario`, so those accepted NaN/Inf bodies now fail *after*
request validation and return **HTTP 500**.

`ScenarioWire.max_loss_pct` still has the exact `Field(gt=0)` + Infinity
hole this slice claimed to close, and `max_loss_pct: NaN` 500s because the
422 handler still serializes raw `nan` in `exc.errors()`.

## Findings

### 1. VALID — Important — Formal scenario wire still accepts NaN/Inf and now 500s

- Files: `backend/app/api/scenario_wire.py` (`FactorShockWire.amount`,
  `ScenarioWire.max_loss_pct`, `FormalCustomStressRequest`),
  `backend/app/risk/scenario_model.py` (`scenario_to_stress`),
  `backend/app/api/stress.py` (`/stress/formal/custom`,
  `/stress/formal/evaluate/custom`),
  `backend/app/domain/models.py` (`StressScenario` now `FiniteFloat`),
  `backend/app/api/errors.py` (`body_from_validation_error` dumps
  `exc.errors()` into `JSONResponse(allow_nan=False)`).
- What's wrong: SEC-006 listed `FactorShockWire.amount` next to equity
  marks and reverse-stress bounds. The wire is still a plain `float`.
  `ScenarioWire.max_loss_pct` still uses `Field(gt=0)`, which accepts
  `+Infinity`. `FormalCustomStressRequest` has no `FiniteInputMixin`.
  This slice then made `StressScenario` finite. Formal posts therefore
  pass request validation and explode in `wires_to_stress` →
  `scenario_to_stress` → `StressScenario(...)`.
- Why it matters: I posted JSON to the live formal routes
  (`raise_server_exceptions=False`):

  | Body | Status |
  |---|---|
  | `amount: Infinity` / `NaN` / `-Infinity` on `/stress/formal/custom` | **500** `internal_error` |
  | `amount: Infinity` on `/stress/formal/evaluate/custom` | **500** |
  | `max_loss_pct: Infinity` | **500** (wire accepts; adapter `FiniteFloat` raises) |
  | `max_loss_pct: NaN` | **500** (request validation fails, then `json.dumps(errors, allow_nan=False)` cannot serialize `input=nan`) |

  `FormalCustomStressRequest.model_validate(..., amount=inf)` **accepts**.
  `FactorShockWire(amount=nan/inf/-inf)` **accepts**. Domain
  `StressScenario(equity_shock=inf)` and legacy `/stress/custom` **reject**.
  SEC-006 verification was “NaN / Infinity bodies return 422 on all
  portfolio-bearing routes.” Formal custom stress is one of those routes.
  The implementer recorded this as an out-of-edit-set leftover. The 500
  is not a leftover of an untouched file: it is produced by tightening
  `StressScenario` without a matching wire constraint. Previously Inf
  could flow into the engine; now the same payload is an uncaught
  `ValidationError` after FastAPI has already accepted the body.
- Suggested fix: Put `FiniteFloat` (and the label rewrite, or an equivalent
  `FiniteInputMixin`) on `FactorShockWire.amount` and
  `ScenarioWire.max_loss_pct`. Add HTTP tests that `amount` /
  `max_loss_pct` `NaN` / `Infinity` return **422** with a JSON-safe body
  on both formal routes. Do not leave rejection to the adapter.

### 2. VALID — Minor — Risk-run `request` blob is rewritten, not rejected

- File: `backend/app/domain/models.py` (`RiskRunCreateRequest.request:
  dict[str, Any]`)
- What's wrong: `FiniteInputMixin` walks the tree and replaces non-finite
  floats with `"NaN"` / `"Infinity"` strings. The create request then
  validates. POST `/api/v1/risk/runs` with `request.x = NaN` returned
  **202** and stored `{"methodology": "DELTA_GAMMA", "x": "NaN"}`.
- Why it matters: Today `execute_run_type` only reads `methodology`, so
  this does not compute with NaN. It will become a silent stringly-typed
  hole if R0.8.4 later puts confidence, shocks, or other scalars in that
  dict. It is not the SEC-006 equity/shock path.
- Suggested fix: Either reject non-finite values anywhere in `request`,
  or leave the blob unconstrained and document that typed run-request
  schemas (R0.8.4) must use `FiniteFloat`. Do not treat stringification
  as validation.

### 3. VALID — Minor — Tests do not pin the 422-not-500 contract beyond `/var` price

- File: `backend/tests/test_finite_scalars.py`
- What's wrong: The HTTP test only hits `/api/v1/risk/var` and only
  asserts `status_code == 422`. It does not parse the body, does not
  cover reverse-stress / legacy custom stress / formal wire, and does
  not cover `FXOptionPosition.pair` or slash/empty pair shapes.
- Why it matters: The `/var` 422 body *is* JSON-safe (I checked). The
  formal 500s in Finding 1 would not fail this file. A future errors-layer
  change that put raw `nan` back into `details.errors[].input` could
  500 the `/var` path while this test still passed.
- Suggested fix: Assert `response.json()` is a validation envelope and
  that `input` is a JSON-safe label. Add one formal-wire case so Finding
  1 cannot regress as 500.

### 4. VALID — Minor — `MarketSnapshot.model_copy` does not re-run finite checks

- File: `backend/app/domain/models.py` (`MarketSnapshot.model_copy`,
  `bump` / `apply`)
- What's wrong: After-validators do not run on `model_copy(update=...)`.
  The override re-freezes nested maps and does not call
  `_assert_nested_floats_finite`. `bump` writes shocked values through
  that path.
- Why it matters: The implementer said bump/apply/diff were intentionally
  unchanged. HTTP construction is still protected. An Inf formal amount
  never reaches `bump` today because the adapter 500s first (Finding 1).
  If a later caller constructs a snapshot and then `bump`s with a
  non-finite amount, Inf/NaN can sit on a frozen snapshot. Not an HTTP
  input-boundary miss for this slice.
- Suggested fix: Re-validate (or construct via `model_validate`) after
  copy/update if bump should refuse non-finite results. Not required to
  close R0.11.2 if the wire rejects first.

## What is not a finding

- Magnitude caps: optional; omitted as requested.
- Query `observations`: already a bounded int; NaN/Inf/0/5001 → 422.
- FX pair policy is shape-only (`^[A-Z]{6}$` after strip/upper). Documented;
  does not claim QA-017 reversal semantics.
- Response-model NaN/Inf sanitization: R0.11.4 / SEC-008, not this slice.
- Result DTOs (`ReverseStressResult`, `StressResult`, …) remain plain
  `float` by design.

## Strengths

- Shared `FiniteFloat` plus the BeforeValidator label rewrite actually
  solves the `/var` 422-vs-500 problem the implementer described.
  `PydanticCustomError` keeps `exc.errors()` JSON-serializable.
- `Field(gt=0)` + Infinity is closed on domain request scalars
  (maturities, vols, reverse-stress bounds, legacy stress shocks).
- `MarketSnapshot` maps and nested curve/surface payloads reject
  non-finite values at construction.
- SAMPLE / DEMO books still construct; demo FX pairs are valid.
- Tests would fail a revert of the domain validator on the cases they
  cover.
