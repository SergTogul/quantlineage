## Summary
When `artifacts` is omitted, `HierarchyEngine.build` and `risk_at` now build a
complete trade-grain `TradeCalculationArtifact` map **once**
(`pricing.value` per position + shared `historical_pnl_for_valuation`) and
then run the existing artifact aggregation path. They no longer call
`_metrics` / `_stress` / `_limits` independently at every hierarchy node.

Explicit `artifacts=` behavior is unchanged (complete map required; fail
closed on incomplete / key mismatch). Node VaR / ES remain VaR / ES of the
**summed** historical vector (loss = −P&L, `numpy.quantile`, floor 0) — parent
VaR is VaR(sum), not sum of child VaRs.

`historical_pnl_for_valuation` was extracted from
`PortfolioService._historical_pnl_for_valuation` into `app.risk.historical`
so the service and hierarchy share one helper (LINEAR / DELTA_GAMMA;
`FULL_REVALUATION` and `factor_panel` still omit the series as `None`).

Default producer stress maps stay empty and limits stay `[]` (same as
`PortfolioService.hierarchy`). Empty position ids use sentinel artifact
`trade_id="__empty__"` while the map key remains `position.id` so
hierarchy-node-id collision tests still work.

review APPROVE.
