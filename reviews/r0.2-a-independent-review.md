Workspace: uncommitted work on `r0-core-remediation` vs HEAD.
Implementer report: `reviews/r0.2-a-report.md`.
Production code was not modified.

## Verdict: REVISE

The conflict adapter and the PortfolioService summary/VaR/ES path are real
improvements and I verified them in source, not from the implementer report.
That is not enough to approve the slice. R0.2-A required a supplied snapshot to
be authoritative and missing required marks to fail. On the production
`pricing.value(trade, market)` path, an incomplete snapshot still silently
reactivates trade-local marks. The required missing-marks test is absent. The
new demo resolver can emit exactly that incomplete snapshot.

## Builtin fallback decision (criterion 9)

`BuiltinPricingEngine.value` and the QuantLib overlay still use
`market.x.get(k, position.mark)` and still accept `market=None`.

- **Unmigrated families (FX, bonds, swaps, IR futures, IR options):** deferred
  family work. R0.2-A's file list does not include `builtin.py` / `quantlib.py`,
  and brief §2 sequences those removals behind family terms. I do not treat
  those leftover `get`s as an R0.2-A implementation defect by themselves.
- **Equity cash spot, which is the family the R0.2-A authority tests are
  written around:** this **does violate R0.2-A**. Brief §7 requires
  `test_market_authority.py` to prove missing required marks fail. The
  production call used by VaR/ES is `pricing.value(trade, market)`, and
  `equity_spots.get(symbol, position.price)` still succeeds when the key is
  absent. That is the brief's "incomplete snapshot silently reactivates
  trade-local market state" hole, not a later-family item.
- **`market is None` on Builtin/QuantLib `value`:** incomplete isolation versus
  `LegacyDemoPricingAdapter`. Cached production wrapping raises; the concrete
  engines do not. Secondary to the incomplete-snapshot case.

The implementer's "fallbacks are deferred family work" statement is therefore
only half right.

## Findings

### 1. VALID — Important — Incomplete snapshot still prices from trade-local marks

- Files: `backend/app/pricing/builtin.py`, `backend/app/pricing/quantlib.py`,
  `backend/tests/test_market_authority.py`
- What's wrong: Production risk engines now pass an explicit `MarketSnapshot`,
  but `BuiltinPricingEngine.value(trade, market)` does
  `market.equity_spots.get(symbol, position.price)` (QuantLib does the same
  overlay). `test_market_authority.py` never asserts that a missing AUTH/SPY
  spot raises `MissingMarketDataError` or any error.
- Why it matters: I priced `EquityPosition(AUTH, qty=10, price=999)` against
  `MarketSnapshot(id="empty")` and against a snapshot that only had `SPY`.
  Both returned `9990.0` — the trade-local mark. VaR/ES/historical LINEAR and
  FULL will silently do the same once they have been given that snapshot.
  This is criterion 6, and it is still true on the production risk path.
- Suggested fix: For equity cash (the A-family already under test), missing
  `equity_spots[symbol]` must raise a typed missing-market error from the
  production `value(trade, market)` path. Add the brief's missing-marks case
  to `test_market_authority.py`. Leave other families to later slices if
  needed, but do not claim A is done while equity spot still falls back.

### 2. VALID — Important — Demo resolver can return an incomplete canned snapshot

- File: `backend/app/sample.py` (`_matching_demo_id`, `demo_market_snapshot`)
- What's wrong: Resolution is `portfolio.id in _DEMO_MARKETS`, else first demo
  whose position-id set is a subset **or superset** of the book. That object
  is what `PortfolioService.market_snapshot` and the VaR/ES `market is None`
  fallback use.
- Why it matters: Probe results:
  - `SAMPLE_PORTFOLIO` plus an `AAPL` equity, id `custom-superset` → matched
    `global-macro`. Snapshot spots are only `NVDA`/`SPY`. AAPL PV came from
    the trade (`1000.0`).
  - Concatenating `EQUITY_VOL_PORTFOLIO` and `RATES_MACRO_PORTFOLIO` → matched
    `equity-vol`. The rates book is then valued through Finding 1 fallbacks.
  - Any persisted/edited book that keeps id `global-macro` / `equity-vol` /
    `rates-macro` gets the canned snapshot even when the position set has
    diverged.
  Together with Finding 1, this is a production authority hole, not just a
  convenience matcher for tests.
- Suggested fix: Bind canned snapshots to exact demo identity (id **and**
  position-id set), or to an explicit snapshot id stored with the book. Do
  not treat supersets as the demo. Extra trades must either have marks in the
  snapshot or fail closed.

### 3. VALID — Minor — Required golden extensions were not added

- Files: `backend/tests/test_var_es_golden.py` (unchanged),
  `backend/tests/test_approx_pnl_units_golden.py` (unchanged).
  `test_full_reval_golden.py` already passed an explicit market before this
  slice; it was not extended to assert service/engine routing.
- What's wrong: Brief §7 required those goldens to assert that the explicit
  snapshot reaches LINEAR / DELTA_GAMMA / FULL_REVALUATION. `test_var_es_golden.py`
  still calls `HistoricalRiskEngine.calculate(UNIT_BOOK, PRICING)` and
  `VaRAnalytics.report(...)` with no `market`. For this unit equity,
  `price == 1.0` equals the adapter-inferred spot, so a regression to
  `pricing.value(p)` without market would still match the literals.
- Why it matters: The named RF-001 mutations are covered elsewhere (criterion
  8). These goldens do not add the snapshot-routing safety net the brief
  asked for.
- Suggested fix: Pass a recording engine plus an explicit snapshot (or a
  snapshot whose spot differs from `position.price`) through LINEAR and
  FULL_REVALUATION in those goldens.

### 4. VALID — Minor — Other service entry points ignore the resolved snapshot

- File: `backend/app/services/portfolio_service.py`
- What's wrong: `contributors()` calls `self.var_engine.report(portfolio, self.pricing)`
  with no market. `compare_var_methodologies()` calls `compare_methodologies`
  without `market` even though that helper accepts one. Both re-infer via
  `demo_market_snapshot`.
- Why it matters: Out of the stated A boundary (summary/VaR/ES first). I
  still confirmed it: after injecting `equity_spots={"AUTH": 105}`,
  `summary().market_value` was `1050` and `contributors()` never touched
  `service.market_data` (0 provider calls). When the service later resolves a
  persisted snapshot instead of the demo factory, these paths will disagree
  with summary/VaR/ES.
- Suggested fix: Pass `self.market_snapshot(portfolio)` into both, same as
  `var_report`.

### 5. VALID — Minor — Production interface still infers markets

- Files: `backend/app/interfaces/pricing.py`, `backend/app/risk/var.py`,
  `backend/app/risk/historical.py`, `backend/app/risk/es.py`
- What's wrong: `PricingEngine.value` is documented as requiring `market`, but
  `shocked_value` and `value_portfolio` still accept `None` and build a
  demo/single-trade snapshot. VaR/ES/historical still default `market=None`
  to `demo_market_snapshot(portfolio)`.
- Why it matters: The *pricing calls* on those paths now pass a snapshot
  (criterion 3). The *methods* still infer a market from trades, which brief
  §1 forbids for production risk calculation. `LegacyDemoPricingAdapter`
  exists but is not the only no-market door.
- Suggested fix: Make engine `market` required; keep inference only on the
  named adapter / demo provider at the application boundary.

## REJECTED items (implementer report)

1. **REJECTED — "Full removal of trade-local fallbacks is intentionally
   deferred to later family slices" as a close-out for R0.2-A.** Deferral is
   valid for unmigrated families. It does not cover equity-spot fallback on
   `pricing.value(trade, market)` or the missing `test_market_authority`
   missing-marks case. Those are in the R0.2-A test list.
2. **REJECTED — implied completeness of `test_market_authority.py`.** The
   file proves A vs B, snapshot-beats-present-spot, adapter isolation, and
   service threading. It does not prove "missing required marks fail."
3. **REJECTED — implied golden-test work for snapshot routing.** The
   implementer ran `test_var_es_golden.py` / `test_full_reval_golden.py` as
   regressions. They did not extend them as brief §7 required, and
   `test_var_es_golden.py` would not fail a no-market LINEAR mutation on
   `UNIT_BOOK`.

I am not rejecting the conflict-adapter, `PositionMarketDataProvider`
wrapper, cache `market:none` rejection, or service summary/VaR/ES
threading claims. Those checked out.
