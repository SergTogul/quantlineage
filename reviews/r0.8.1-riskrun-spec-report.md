## Summary
`RiskRun` now carries optional first-class spec identities: `historical_dataset_id`, `historical_dataset_version`, `as_of` (same `AsOf` type as `MarketSnapshot`: calendar `date` or `current` / `t0`), and `calculation_config` (`RiskRunCalculationConfig`: `observations`, `seed`, `confidence`; `extra="forbid"`, no secrets). Omitted fields remain valid so pre-spec rows load. Memory and SQLite persistence round-trip the new fields. Alembic `003_risk_run_spec_fields` adds nullable columns. API vs worker factory unification is R0.8.2 and was not implemented. No VaR numbers were changed.

## Known limitations / risks
- Spec fields are optional and are **not** filled by `RiskRunService.enqueue` or the create-run API. Existing interactive and worker paths still omit them unless a caller sets them.
- RF-009 remains open: API and worker can still construct historical engines from different datasets/defaults (R0.8.2).
- `calculation_config` is a closed set of knobs (`observations`, `seed`, `confidence`), not a generic blob. Further methodology extras need an explicit field add.
- `request` remains the generic envelope (R0.8.4 typed run requests).
- No portfolio version field was added (already had `portfolio_id`; version is out of this leftover slice).
