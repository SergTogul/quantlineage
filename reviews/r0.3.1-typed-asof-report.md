## Summary

`MarketSnapshot.as_of` is no longer an unconstrained `str`. It is a bounded union:

```text
AsOf = date | Literal["current", "t0"]
```

ISO `YYYY-MM-DD` strings coerce to `datetime.date`. Engine labels `current` and `t0` stay labels and mean “use the pricing-engine evaluation date.” They are never rewritten to `date.today()` on the production path. Anything else (`later`, `t1`, `illustrative_previous`, empty, unpadded dates, `datetime`) fails closed at construction.

Persistence and API still store `as_of` as a string. `as_of_wire` is the adapter: calendar dates become ISO; labels stay labels. QuantLib and the valuation cache use `calendar_as_of` so a typed `date` drives `Settings.evaluationDate` and cache identity.

## Chosen type

`date | Literal["current", "t0"]` (`AsOf`), with `BeforeValidator` coercion.

Rejected alternative: `as_of: date` only, mapping labels to `date.today()`. That would silently bind demo/fixture snapshots to wall-clock and break reproducibility.

## Numerical conventions

- Units / methodology: unchanged. No pricing formula changes.
- Evaluation date: typed calendar `as_of` drives QuantLib `Settings.evaluationDate` for that call. Engine labels keep `QuantLibPricingEngine.evaluation_date` (constructor default remains `date.today()` — that is engine construction, not snapshot coercion).
- Day count/calendar: ISO calendar date only (`YYYY-MM-DD`). `datetime` is rejected (`datetime` is a `date` subclass).
- Tolerances: existing QuantLib process-state spies compare exact `ql.Date` values.

## Known limitations / risks

- Engine labels remain a documented demo/fixture form. Production snapshots that need a reproducible evaluation date must supply ISO or `date`.
- `QuantLibPricingEngine()` still defaults `evaluation_date` to `date.today()` when no parseable snapshot `as_of` is present. That is engine construction, not silent snapshot rewriting.
- Persistence `as_of` column stays `String(64)`. Historical rows with ISO or `current` load; rows with other free-text labels will fail closed on `model_validate`.
- `model_construct` can still bypass validation; `calendar_as_of` parses ISO there but does not raise on garbage (cache/QuantLib treat it as “use engine date”).
